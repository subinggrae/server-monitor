# 0014. monitoring 네트워크는 운영자가 만들고 모니터링 시스템과 관리자 서버가 함께 붙는다

- 상태: 승인
- 날짜: 2026-11-16
- 관련: [요구사항 0019](../requirements/0019-monitoring-external-network.md), [ADR 0007](0007-core-app-contract.md)(이 ADR이 그 결정 가운데 네트워크를 만든다는 문장과, 그에 따른 감수할 점 "코어를 먼저 띄워야 앱을 띄울 수 있다"만 대신함)

## 배경과 문제

[ADR 0007](0007-core-app-contract.md)은 모니터링 시스템(당시 이름은 코어)이 compose 파일로 Docker 네트워크 `monitoring`을 만들고, 관리자 서버가 그 네트워크에 붙게 했다. 그래서 관리자 서버는 모니터링 시스템이 떠 있어야만 띄울 수 있었다. 또 모니터링 시스템을 `docker compose down`으로 내리면 Compose가 네트워크를 지우려 했다. 관리자 서버가 붙어 있으면 경고가 나고, 붙어 있지 않으면 네트워크가 사라져 관리자 서버를 다시 띄울 때 실패했다. 두 쪽의 연결이 모니터링 시스템의 Compose 동작에 묶여 있었다.

## 검토한 선택지

- **모니터링 시스템의 compose 파일이 계속 만듦**: 운영자 할 일이 없다 / 띄우는 순서가 묶이고, 내릴 때 네트워크가 지워지거나 경고가 난다.
- **운영자가 한 번 만들고 두 쪽이 모두 `external: true`로 붙음**: 띄우는 순서와 내리는 동작이 서로 묶이지 않는다 / 처음 설치할 때 명령이 하나 늘고, 만들지 않으면 띄우지 못한다.
- **운영 명령(`monitoring-server.sh`)이 없을 때 만듦**: 운영자 할 일이 늘지 않는다 / 서버를 바꾸는 일은 운영 가이드로 안내하고 운영 명령은 최소로 둔다는 방침과 맞지 않는다.

## 결정

`monitoring` 네트워크는 운영자가 모니터링 서버를 처음 준비할 때 `docker network create monitoring`으로 한 번 만든다. 모니터링 시스템과 관리자 서버는 모두 `external: true`로 이미 있는 네트워크에 붙고, 만들거나 지우지 않는다. 운영 명령 `start`는 네트워크가 없으면 띄우기 전에 멈추고 만드는 명령을 알린다. 네트워크 이름 `monitoring`과 옵션(Docker 기본 bridge)은 바꾸지 않는다(사람 확인: 2026-11-16).

## 결과

- 좋아지는 점: 모니터링 시스템과 관리자 서버 어느 쪽을 먼저 띄워도 된다. 모니터링 시스템을 내리거나 갱신해도 네트워크와 관리자 서버의 연결이 남는다.
- 감수할 점: 새 서버에서는 운영자가 네트워크를 먼저 만들어야 한다. 빠뜨리면 운영 명령이나 Compose가 띄우지 않고 멈춘다.
- 다시 볼 신호: 모니터링 시스템과 관리자 서버를 다른 서버에 나눠 둘 때([#15](https://github.com/subinggrae/server-monitor/issues/15))

## 확인 방법

- 운영 명령 시험(`infrastructure/tests/monitoring-server.test.sh`)이 네트워크가 없으면 `start`가 멈추고, 운영 명령이 네트워크를 만들지 않는지 본다.
- `infrastructure/compose.yml`의 네트워크가 `external: true`인지는 리뷰에서 확인한다.
