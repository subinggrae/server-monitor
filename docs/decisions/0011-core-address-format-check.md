# 0011. 코어의 시작 스크립트도 관리자 서버 주소의 형식을 운영 명령과 같은 규칙으로 검사한다

- 상태: 승인
- 날짜: 2026-11-09
- 관련: [요구사항 0013](../requirements/0013-core-env-settings.md)(S16, C10), [ADR 0007](0007-core-app-contract.md)(이 ADR이 그 결정 가운데 앱 주소의 형식을 검사하지 않는다는 문장만 대신함), [#33](https://github.com/subinggrae/server-monitor/issues/33)

## 배경과 문제

[ADR 0007](0007-core-app-contract.md)은 코어가 부르는 앱 주소를 `MONITORING_APP_ADDRESS` 하나로 받아 `render-config.sh`가 설정 템플릿에 펼치기로 했다. 같은 결정에서, 공격자가 이 값을 넣을 경로가 없으므로 형식은 검사하지 않기로 했다.

그 뒤 사정이 바뀌었다.

- 코어 서버의 운영 명령(`core-server.sh`, [요구사항 0011](../requirements/0011-core-ops-script.md))은 이 값을 `컨테이너 이름:포트` 형식으로 검사한다. 그러나 운영 명령 없이 Compose로 띄우면 시작 스크립트가 검사하지 않은 값을 Prometheus와 Alertmanager 설정에 그대로 펼친다.
- [요구사항 0013](../requirements/0013-core-env-settings.md)은 서버에서 바꾸는 코어 값을 열면서, 설정에 펼치는 값은 검사를 통과한 것만 펼치기로 했다.

앱 주소도 묶음 폴더에 쓸 수 있는 운영자만 바꾼다. 하지만 복사해 붙인 값이나 셸에 남은 환경 변수처럼 운영자가 의도하지 않은 값이 들어올 수 있다. 형식에 맞지 않는 값을 그대로 펼치면 주소가 아닌 다른 설정 항목까지 영향을 받을 수 있다. 2026-11-09 0013의 구현 리뷰에서 이 차이를 찾았다.

## 검토한 선택지

- **지금처럼 운영 명령만 검사**: 바꿀 것이 없다 / 운영 명령 없이 띄우면 형식이 틀린 값이 설정에 그대로 들어간다.
- **시작 스크립트에 같은 규칙을 따로 씀**: 운영 명령 쪽 코드를 건드리지 않는다 / 규칙이 두 곳에 생겨 한쪽만 고칠 수 있다.
- **시작 스크립트가 값을 바꿔 안전한 글자로만 펼침**: 형식이 틀려도 코어가 뜬다 / 틀린 주소가 목록 갱신과 장애 전달의 실패로만 드러나 원인을 찾기 어렵고, 운영 명령과 받는 값이 달라진다.
- **공용 검사 함수 하나를 두 곳이 씀**: 규칙이 한곳에 있고 운영 명령과 받는 값이 같다 / 묶음과 이미지에 같은 파일이 함께 들어가야 한다. 이 파일은 0013에서 이미 함께 싣는다.

## 결정

공용 검사 함수 하나를 두 곳이 쓴다(사람 확인: 2026-11-09).

- `infrastructure/core-settings.sh`의 `core_valid_address`가 규칙을 정한다. 형식은 `컨테이너 이름:포트`다. 이름은 영문자나 숫자로 시작하고 영문자, 숫자, `_`, `.`, `-`만 쓰며, 포트는 1~65535다. 운영 명령이 이전부터 받던 형식 그대로다.
- 함수는 값 전체를 한 번에 보고, 글자를 범위로 쓰지 않고 나열해 비교한다. locale에 영향을 받지 않게 하기 위해서다.
- 운영 명령은 띄우기 전에 이 함수로 검사하고, 검사한 값을 그대로 Compose에 넘긴다.
- 시작 스크립트는 템플릿에 앱 주소 자리표시가 있을 때 이 함수로 검사하고, 틀리면 원래 프로세스를 실행하지 않는다. 로그에는 적힌 값, 맞는 형식, 고치는 방법을 남긴다.

이 ADR은 ADR 0007의 결정 가운데 "공격자가 이 값을 넣을 경로가 없으므로 형식을 검사하지 않는다"는 문장만 대신한다. 앱 주소를 한 값으로 받아 시작할 때 펼치는 방식과 0007의 나머지 결정은 그대로다. ADR 템플릿에는 일부만 대체하는 것을 표시하는 상태 값이 없어서 0007은 고치지 않고, 이 ADR에서 0007을 가리킨다.

## 결과

- 좋아지는 점:
  - 운영 명령을 쓰든 쓰지 않든 형식이 맞는 주소만 설정에 들어간다.
  - 두 곳의 규칙이 어긋날 수 없다.
- 감수할 점:
  - 운영 명령 없이 형식이 틀린 주소로 띄우던 서버는, 이 변경이 든 버전으로 갱신하면 `prometheus`와 `alertmanager`가 시작하지 않는다. 운영 가이드의 운영 명령 없이 실행과 문제 해결에 안내가 있다.
  - 주소 형식을 넓히려면 이 함수와 그 시험을 함께 고친다.
- 다시 볼 신호: 컨테이너 이름이 아닌 주소(IPv6, 다른 호스트의 주소 등)를 받아야 할 때. 코어와 앱을 다른 호스트에 두는 구성([#15](https://github.com/subinggrae/server-monitor/issues/15))이 그 예다.

## 확인 방법

- 빌드 검사(`node scripts/build-core-bundle.mjs --check`): Prometheus와 Alertmanager 이미지마다 형식에 맞지 않는 여러 주소를 시작 스크립트가 거부하고 원래 프로세스를 실행하지 않는지 본다(`checkRejectedAddresses`).
- 운영 명령 시험(`infrastructure/tests/core-server.test.sh`): 틀린 주소를 거부하는지, 검사한 주소가 그대로 Compose에 넘어가는지 본다.
