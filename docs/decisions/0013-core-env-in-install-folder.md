# 0013. 코어 설정 파일은 설치 폴더에 하나만 두고, 묶음 폴더에는 그 파일을 가리키는 링크를 둔다

- 상태: 승인
- 날짜: 2026-11-11
- 관련: [요구사항 0017](../requirements/0017-core-shared-env.md), [PR #53](https://github.com/subinggrae/server-monitor/pull/53)(구현 계획 포함), [요구사항 0015](../requirements/0015-core-minimal-image.md), [ADR 0012](0012-core-render-outside-image.md)

## 배경과 문제

코어 설정 파일(`.env`)을 버전마다 묶음 폴더 안에 두므로, 새 버전으로 갱신할 때마다 이전 폴더의 `.env`를 복사해야 했다. 사람이 이 복사가 번거롭다고 하고, 설치 폴더에 하나만 두어 모든 버전이 함께 읽게 하기로 했다(2026-11-11, 요구사항 0017).

그런데 이 파일은 운영 명령만 읽는 것이 아니다. docker compose는 프로젝트 폴더(묶음 폴더)의 `.env`를 자동으로 읽어 compose 파일의 호스트 포트(`CORE_*_PORT`)와 token 폴더(`CORE_SECRETS_DIR`)를 채운다. 운영 가이드는 멈추기, 로그 보기, token 바꾸기에 묶음 폴더의 `docker compose` 명령을 그대로 쓰게 한다. 그래서 설정 파일을 옮기면 이 명령들이 어디서 값을 읽을지도 함께 정해야 한다.

## 검토한 선택지

- **묶음 폴더에 그대로 두고 갱신할 때 복사**: 바꿀 것이 없다 / 사람이 번거롭다고 한 지금 방식이다.
- **운영 명령이 이전 버전의 `.env`를 새 폴더로 복사**: 운영자가 할 일이 없다 / 운영 명령에 파일 복사 기능이 늘어 최소 기능 원칙(요구사항 0015)과 맞지 않고, 사람이 자동 복사를 하지 않기로 했다.
- **설치 폴더에 두고 compose를 부를 때마다 `--env-file ../.env`**: 링크가 없다 / 운영자가 수동 명령에서 이 옵션을 빠뜨리면 Compose가 기본 포트와 기본 token 폴더로 컨테이너를 다시 만들고, 오류 없이 틀린 값으로 돈다.
- **설치 폴더에 두고 묶음 폴더에 `../.env` 링크**: 운영 가이드의 compose 명령을 바꾸지 않아도 같은 값을 읽는다 / 운영 명령이 링크를 만들어야 하고, 운영 명령 없이 띄울 때는 운영자가 링크를 만든다.

## 결정

설치 폴더에 `.env`를 하나만 두고, 운영 명령(`install`, `render`, `start`)이 묶음 폴더에 `../.env`를 가리키는 상대 링크를 만든다. 운영 명령은 설치 폴더의 파일을 읽는다. docker compose는 묶음 폴더의 링크를 따라 같은 파일을 읽는다(2026-11-11에 `docker:cli` 컨테이너의 `docker compose config`로 확인). 그래서 운영자가 기억할 옵션이 없고, 빠뜨려서 조용히 틀어질 곳도 없다.

다만 링크 때문에 다른 파일을 건드리지 않도록 운영 명령은 다음을 지킨다.

- 설정 파일은 읽기만 하고, 링크를 거쳐 쓰지 않는다.
- 묶음 폴더의 `.env`가 `../.env`가 아닌 곳을 가리키는 링크이거나 별도의 파일이면 따라가지 않고 멈춘다.

이전 방식으로 쓰던 파일을 찾으면, 직접 옮기지 않고 복사할 명령만 보인다.

## 결과

- 좋아지는 점: 갱신할 때 옮길 파일이 없다. 설정 파일, token, CA 인증서 파일을 모두 설치 폴더에 두므로 버전 폴더는 지워도 되는 내용만 남는다.
- 감수할 점: 이전 버전으로 되돌려도 설정은 되돌아가지 않는다. 설정 파일을 묶음 폴더에 두던 버전으로 되돌리면 그 버전은 자기 폴더의 `.env`를 읽으므로, 두 파일의 값이 다를 수 있다.
- 다시 볼 신호: 링크를 만들 수 없는 파일 시스템에 설치해야 하거나, 버전마다 다른 설정이 필요해지면 다시 본다.

## 확인 방법

- 운영 명령 시험(`infrastructure/tests/core-server.test.sh`): `install`이 설치 폴더에 파일을 만들고 묶음 폴더에는 `../.env` 링크만 두는지 본다. `start`와 `render`가 링크를 만드는지도 본다. 또 이전 방식의 파일이나 다른 곳을 가리키는 링크가 있으면 코어를 바꾸지 않고 멈추는지 본다.
- 코어 서버에서 수동 확인: 설치 폴더의 `.env`에서 포트를 바꾸고 띄운 뒤, 묶음 폴더에서 `docker compose config`를 실행해 바꾼 포트가 나오는지 본다.
