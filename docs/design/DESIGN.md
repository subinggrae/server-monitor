# 디자인

이 문서는 이 제품의 시각 체계를 적은 것으로, 화면을 만들거나 고칠 때마다 읽는다. 함께 보는 내용은 다음 문서에 있다.

- 대상과 말투: [PRODUCT.md](../PRODUCT.md)
- 모든 화면에 적용하는 규칙: [RULES.md](RULES.md)
- 만들기 전과 만든 뒤의 점검: [REVIEW.md](REVIEW.md)
- 시각 체계를 정하는 방법, 참고 화면을 찾는 방법, 트렌드를 검토하는 방법: [DIRECTION.md](DIRECTION.md)

개요부터 해야 할 것과 하지 말 것까지의 절 순서는 AI 도구가 읽는 디자인 시스템 설명 형식([Google DESIGN.md](https://github.com/google-labs-code/design.md))을 따른다. 그 형식은 토큰 값을 파일 머리에 두지만, 이 문서는 값을 코드의 토큰 파일에 두고 토큰 이름만 쓴다.

아래 시각 체계는 [요구사항 0005](../requirements/0005-design-overhaul.md)에서 [DIRECTION.md](DIRECTION.md)의 순서로 정했다. 토큰 값은 0005를 구현할 때 토큰 파일에 둔다. 그전까지 토큰 파일의 값은 이 문서와 다를 수 있다.

## AI가 만드는 범위

디자이너나 퍼블리셔에게 받은 디자인이 있으면 그 범위의 화면은 받은 디자인대로 옮긴다. 반면 이 문서와 규칙 파일은 AI가 만드는 범위의 화면에 쓴다.

받은 디자인이 없다. 모든 화면을 AI가 만든다.

## 개요

이 제품의 시각 체계를 요약하고, 화면을 검사할 도구와 승인 기록을 함께 적는다.

- 스타일: 조밀한 무채색 운영 콘솔. 바탕과 글자는 무채색이고, 색은 상태에만 쓴다. 정보는 카드가 아니라 표와 구분선으로 나눈다.
- 원하는 인상: 정상일 때는 조용하고, 문제가 있을 때만 분명하다. 처음 연 사람이 3초 안에 "무엇이, 언제부터"를 읽는다.
- 참고 화면: 2026-10-15에 확인했다. 화면을 그대로 따르지 않고 아래 속성만 가져온다.
  - [Uptime Kuma](https://github.com/louislam/uptime-kuma): 지금 상태 옆에 시간 맥락(언제부터, 최근 기록)을 함께 보인다.
  - [Vercel Geist](https://vercel.com/geist/introduction): 색 토큰마다 쓰임새(바탕, 경계선, 글자)를 정하고, 움직임은 진행 중이라는 뜻이 있을 때만 쓴다.
  - [Linear UI 재설계](https://linear.app/now/how-we-redesigned-the-linear-ui): 적은 입력값에서 밝은 테마와 다크 테마를 함께 만들고, 크롬의 색을 줄여 내용을 앞에 둔다.
  - 피할 화면: [Grafana Node Exporter Full](https://grafana.com/grafana/dashboards/1860-node-exporter-full/). 패널 141개와 원형 gauge를 나란히 두어 "지금 무엇이 문제인가"에 답하지 못한다.
- 화면 검사 도구: 전체 실행 환경을 띄운 뒤 `frontend`에서 실행한다.
  - 접근성과 가로 넘침: `npm run test:screen`. Playwright에서 axe-core로 WCAG 2.2 AA를 검사하고, 기준 폭과 밝은·다크 모드마다 모든 라우트, 추가 대화상자, API가 실패한 오류 상태를 연다. 기준선은 없다.
  - 성능: `npm run test:perf`. Lighthouse로 대시보드의 점수와 LCP, CLS, TBT를 본다.
  - 흔한 기본값: 도구 없이 [REVIEW.md의 코드 점검](REVIEW.md#코드-점검) 목록을 코드 검색으로 확인한다.
- 승인: 화면 검사 도구와 기준 폭은 사람이 2026-10-14에, 시각 체계와 [화면 틀](#화면-틀)은 2026-10-15에 미리 보기 페이지로 확인했다. 브랜드를 살린 컴포넌트 모양은 회사 브랜드 자료를 받은 뒤 확인한다.

## 토큰

토큰은 다음 파일에 있다.

- 토큰 파일: `frontend/src/index.css`. CSS 변수로 값을 정하고 Tailwind의 `@theme inline`으로 노출한다. `tailwind.config` 파일은 없다.

## 색

색은 다음 토큰으로 쓴다.

- 주조색: `--primary`는 거의 검정인 먹색이다. 주요 버튼과 선택된 메뉴에만 쓴다.
- 강조색: 위험(`--status-critical`) 하나를 날카롭게 둔다. 주의(`--status-warning`)는 그보다 한 단계 낮게, 정상(`--status-ok`)은 점과 아이콘에만 채도를 낮춰 쓴다. 정상이 화면에서 가장 많으므로 눈에 띄지 않아야 한다.
- 역할: 배경 `--background`, 표면 `--surface`, `--surface-subtle`, `--sidebar`, 글자 `--foreground`, `--muted-foreground`, `--subtle-foreground`, 경계선 `--border`, `--border-strong`, 상태 `--status-ok`, `--status-critical`, `--status-warning`, `--status-neutral`, 상태 글자 `--status-critical-foreground`, `--status-warning-foreground`, 초점 `--ring`
- 대비: 글자 토큰은 모두 그 글자가 놓이는 가장 어두운(다크 모드는 가장 밝은) 바탕에서 4.5:1 이상이다. `--subtle-foreground`도 같다. 상태 점과 아이콘은 바탕에서 3:1 이상이다. 투명도를 낮춰 만든 색을 글자와 상태 표시에 쓰지 않는다.
- 다크 모드: 운영체제 설정(`prefers-color-scheme`)을 따른다. 밝은 모드와 같은 이름의 토큰을 다시 정하고, 같은 대비 기준을 지킨다.

## 글자

글꼴과 글자 크기는 다음처럼 정한다.

- 글꼴: Pretendard Variable 하나로 제목과 본문을 함께 쓴다. 한글과 라틴, 숫자의 굵기와 높이가 맞고, 숫자 폭을 맞추는 `tnum`과 0과 O를 가르는 `zero`가 있다. 글꼴 파일은 화면과 함께 배포하고(사내망에서 CDN을 쓸 수 없을 수 있다) `font-display: swap`으로 불러온다. 라이선스는 SIL OFL 1.1이다([LICENSES.md](../LICENSES.md)).
- 크기: 단계는 `--text-caption`, `--text-body`, `--text-section`, `--text-page`, `--text-figure` 다섯이다. 본문 위의 단계는 앞 단계보다 1.25배 이상 크다. `--text-figure`는 대시보드의 위험 수처럼 화면에서 가장 먼저 읽을 숫자에만 쓴다.
- 굵기: 본문 400, 라벨과 표 머리글 500, 제목 600, `--text-figure` 700. 굵기로만 위계를 만들지 않고 크기와 색을 함께 쓴다.
- 숫자: 표의 숫자, IP, 시각은 `tnum`으로 자리수를 맞춘다(`.tabular`). IP와 포트처럼 0과 O를 헷갈리면 안 되는 값에는 `zero`도 켠다.
- 한국어는 어절 단위로만 줄을 바꾼다(`word-break: keep-all`). 표 안의 숫자와 IP는 `.tabular` 클래스로 자리수를 맞춘다.

## 레이아웃과 간격

화면 배치와 간격, 기준 폭은 다음과 같다.

- 배치: 왼쪽 고정 사이드바와 최대 폭을 둔 본문(`AppLayout`). 본문은 위에서 아래로 일반에서 구체로 내려간다. 대시보드는 위험 → 최근 Alert → 나머지 순서다.
- 간격 단계: 4px 단위의 Tailwind 간격(1, 2, 3, 4, 6, 8, 12)만 쓴다. 표 행 안은 촘촘하게, 절과 절 사이는 넓게 두어 묶음을 간격으로 보인다.
- 정보 묶음: 절 제목과 구분선으로 나누고, 카드로 감싸지 않는다. 표는 한 겹의 테두리만 둔다.
- 기준 폭: 1280×800, 1920×1080. 사무실 데스크톱 브라우저에서만 쓴다.

### 화면 틀

모든 화면은 아래 틀 가운데 하나로 만들고, 틀이 정한 자리에만 내용을 넣는다. 화면 코드가 제목, 도구 막대, 본문 자리를 따로 짜지 않는다. 틀 컴포넌트는 `frontend/src/components/layout/`에 둔다.

| 틀 | 자리(위에서 아래) | 쓰는 화면 |
|---|---|---|
| 목록 | 머리(제목, 설명, 주요 동작 하나) → 알림 띠 → 도구 막대(검색, 필터, 적용 중인 필터, 건수) → 표 → 보조 절 | 감시 항목, 서버, 장애 기록, Telegram 그룹 |
| 상세 | 머리(목록으로, 제목, 상태, 메타, 수정·삭제) → 요약 → 탭이나 절 | 감시 항목 상세, 서버 상세 |
| 개요 | 머리(제목, 마지막 확인 시각, 바깥 링크) → 핵심 숫자 → 우선 절 → 나머지 절 | 대시보드 |
| 설정 | 머리(제목, 설명) → 절(제목, 설명, 동작) 여러 개 | 설정 |
| 대화상자 폼 | 제목, 설명 → 필드 → 폼 오류 → 아래 막대([닫기] [실행]) | 추가·수정 대화상자, 삭제 확인 |

틀마다 지킬 것은 다음과 같다.

- **머리**: 화면을 불러오는 중이거나 실패해도 머리(특히 "목록으로")는 그대로 둔다. 주요 동작은 머리 오른쪽에 하나만 둔다. 두 번째 동작부터는 보조 버튼이다.
- **안내 문구**: 화면 전체에 걸린 안내와 경고는 머리 아래 알림 띠 하나에만 둔다. 표 아래 문단으로 두지 않는다.
- **목록의 빈 상태**: 빈 상태에는 머리의 주요 동작을 같은 문구로 한 번 더 둔다. 필터 결과가 없으면 표 안에 "조건에 맞는 항목이 없습니다"와 필터 초기화를 둔다.
- **절의 조회 상태**: 절마다 불러오는 중은 자리 틀(skeleton), 실패는 문구와 [다시 시도], 비어 있음은 한 줄 문구로 보인다. 절을 통째로 숨기지 않는다.
- **절 안의 폼**: 저장 버튼은 폼 아래 왼쪽에 [저장] 하나를 두고, 결과 문구("저장했습니다", 오류)는 그 버튼 옆에 둔다. 절 머리에는 폼 밖의 동작(검색, 해제)만 둔다.
- **상세의 요약**: 설명과 주요 속성은 요약 자리의 속성 목록에 둔다. 같은 대화상자를 여는 버튼을 두 곳에 두지 않는다.
- **대화상자 폼**: 필드는 한 줄에 하나씩 쌓는다. 짧은 값 둘(종류와 환경처럼)만 한 줄에 둘 수 있다. 폼 오류는 아래 막대 바로 위에 두고, 제출하면 첫 오류 칸으로 포커스를 옮긴다. 아래 막대는 [닫기]가 왼쪽, 실행 버튼이 오른쪽이다.

## 깊이

화면 요소의 깊이는 다음처럼 표현한다.

- 엘리베이션: 바닥 층은 경계선(`--border`)으로만 나누고 그림자를 쓰지 않는다. 대화상자처럼 화면 위에 떠서 다른 내용을 가리는 층에만 그림자 토큰 `--shadow-overlay` 하나를 쓴다.

## 모양

화면 요소의 모양은 다음을 따른다.

- 모서리: `--radius`에서 만든 `sm`, `md`, `lg`. 작은 모서리로 조밀한 인상을 지키고, 알약 모양(완전히 둥근 모서리)은 상태 점에만 쓴다.

## 컴포넌트

컴포넌트와 아이콘은 다음에서 가져온다.

- 컴포넌트 위치: `frontend/src/components/ui`. shadcn/ui(`components.json`의 `new-york` 스타일)를 바탕으로 줄여 만들었고, Radix는 Dialog 하나만 쓴다.
- 아이콘: lucide-react

여러 화면에서 반복되는 패턴과 그 규칙을 적는다.

| 패턴 | 규칙 |
|---|---|
| 조회 상태 | 불러오는 중, 오류, 빈 상태를 `QueryStates`의 컴포넌트로 보인다 |
| 상태 표시 | `StatusDot`으로 모양과 문구를 함께 보인다 |
| 삭제 확인 | `ConfirmDialog`에 무엇이 사라지는지 구체적으로 적는다 |
| 입력 오류 | API가 돌려준 칸별 오류를 해당 입력 칸 아래에 보인다 |

표에 다 적지 못한 규칙은 다음과 같다.

- **조회 상태**: 표를 불러오는 동안 화면 전체를 막지 않고 표 자리를 남겨 둔다(`TableSkeleton`). 오류와 빈 상태는 `ErrorState`, `EmptyState`로 보인다.
- **상태 표시**: 색만으로 상태를 구분하지 않는다. 같은 모양을 색만 바꿔 쓰지 않도록 위험은 점 대신 경고 아이콘, 나머지는 점으로 그린다. Check, 서버, Resource, Alert의 상태를 모두 이 컴포넌트로 그린다. 상태가 행동이 필요 없는 것(정상, 사용 안 함)이면 글자를 강조하지 않는다.
- **입력 오류**: 오류가 난 칸에 `aria-invalid`를 켠다. 칸별 오류가 없으면 [화면 틀](#화면-틀)의 폼 오류 자리에 보인다.

## 움직임

움직임을 쓰는 곳과 그 길이, 곡선은 다음과 같다.

- 쓰는 곳: 누를 수 있는 요소의 가리키기와 누르기 색 변화, 대화상자가 열리고 닫힐 때, 대시보드가 새로고침하는 동안의 진행 표시뿐이다. 진행이 끝나면 멈춘다. 위험 상태를 깜박이거나 움직이게 하지 않는다. 계속 움직이는 경보는 경보 피로를 만든다.
- 길이와 곡선: `--duration-fast`(색 변화), `--duration-base`(대화상자)와 감속 곡선 `--ease-out` 하나다. 동작 줄이기 설정에서는 길이를 0으로 둔다.

## 배경

화면 배경은 다음처럼 표현한다.

- 배경 표현: 단색(`--background`)이다. 그라디언트와 무늬를 검토했지만 쓰지 않는다. 이 화면의 주인공은 표와 상태이고, 배경의 깊이 표현은 위험 표시와 주의를 다투며 표 위 글자의 대비를 고르지 않게 만든다.

## 해야 할 것과 하지 말 것

이 제품에서 나오기 쉬운 흔한 기본값과 그 대신 쓸 것은 다음과 같다.

- 이유 없이 고른 시스템 글꼴 대신 Pretendard Variable을 쓴다.
- 정보에 비해 큰 컨테이너, 카드 안의 카드, 숫자 하나씩 담은 통계 카드 줄 대신 표와 한 줄 요약을 쓴다.
- 모든 섹션 위에 되풀이한 작은 라벨 대신 절 제목 하나만 둔다.
- 경고 배너의 한쪽 가장자리만 굵은 색 테두리 대신 상태 아이콘과 제목 문장으로 알린다.
- 색 바탕 위의 회색 글자, 투명도로 흐리게 만든 글자 대신 대비를 지킨 글자 토큰을 쓴다.
- 원형 gauge와 꾸미기용 차트 대신 숫자와 단위를 쓰고, 추세는 Grafana 링크로 넘긴다.

## 화면을 만드는 순서

화면 하나는 다음 순서로 만든다.

1. 시각 체계가 정해졌는지 확인한다. 개요가 "아직 정하지 않았다."이거나 승인 줄에 시각 체계를 확인한 날짜가 없으면 [DIRECTION.md](DIRECTION.md)의 순서로 먼저 정하고 승인받는다.
2. 이 화면이 받은 디자인의 범위인지 [AI가 만드는 범위](#ai가-만드는-범위)에서 확인한다. 받은 디자인의 범위면 그 디자인을 프로젝트의 컴포넌트와 토큰으로 옮긴다.
3. [REVIEW.md](REVIEW.md)의 순서대로 만들기 전 점검, 만들기, 코드 점검, 화면 점검을 한다.
4. 새 패턴이 생기면 컴포넌트 절의 표에 더한다.
