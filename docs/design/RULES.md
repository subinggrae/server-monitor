# 디자인 규칙

모든 화면에 적용하는 규칙이다. 화면을 만들 때와 리뷰할 때 읽는다. [Vercel Web Interface Guidelines](https://vercel.com/design/guidelines)의 분류를 따르고, 화면 코드에 적용하는 규칙을 옮겼다. 점검 순서와 판정은 [REVIEW.md](REVIEW.md), 이 제품의 결정은 [DESIGN.md](DESIGN.md)에 있다. 이 프로젝트가 이 파일과 다르게 정한 것은 [DESIGN.md의 고정 규칙과 다르게 정한 것](DESIGN.md#고정-규칙과-다르게-정한-것)에 있고, 그 절이 이 파일보다 앞선다.

## 접근성

- 의미에 맞는 HTML 요소(`button`, `a`, `label`, `table`)를 먼저 쓰고, 없을 때만 ARIA를 쓴다.
- 동작은 `button`, 이동은 `a`로 만든다. 클릭 처리를 붙인 `div`를 쓰지 않는다.
- 아이콘만 있는 버튼과 라벨이 없는 입력 요소에는 `aria-label`을 단다.
- 이미지에는 `alt`를 단다. 꾸미기용 이미지는 `alt=""`, 꾸미기용 아이콘은 `aria-hidden="true"`로 둔다.
- 알림과 검증 결과처럼 나중에 바뀌는 내용은 `aria-live="polite"`로 알린다.
- 제목은 `h1`부터 단계를 건너뛰지 않는다. 본문으로 건너뛰는 링크를 둔다.
- 글자 대비는 WCAG 기준을 지킨다. 반투명 표면이나 이미지 위 글자는 대비가 가장 낮은 지점에서 잰다.

## 포커스

- 누를 수 있는 요소는 포커스가 보인다. 대신할 표시 없이 `outline: none`을 쓰지 않는다.
- `:focus` 대신 `:focus-visible`을 쓴다. 마우스로 누를 때는 포커스 테두리가 나오지 않는다.
- 여러 요소로 된 컨트롤은 `:focus-within`으로 묶어 표시한다.
- 고정된 헤더, 푸터, 겹친 층이 포커스된 요소를 가리지 않는다.

## 폼

- 입력 요소에 맞는 `type`, `inputmode`, `autocomplete`, 의미 있는 `name`을 단다.
- 라벨을 누르면 입력 요소가 선택된다. 체크박스와 라디오는 라벨과 컨트롤 사이에 누를 수 없는 틈이 없다.
- 붙여넣기를 막지 않는다.
- 제출 버튼은 요청이 시작될 때까지 누를 수 있고, 요청 중에는 진행 표시를 보인다.
- 오류는 입력 칸 옆에 보이고, 제출하면 첫 오류로 포커스를 옮긴다. 오류가 나도 입력한 값은 지우지 않는다.
- 저장하지 않은 변경이 있으면 페이지를 떠나기 전에 알린다.

## 움직임

- 동작 줄이기 설정(`prefers-reduced-motion`)에서는 움직임을 줄이거나 끈다.
- `transform`과 `opacity`만 움직인다. `transition: all`을 쓰지 않고 속성을 나열한다.
- 움직이는 중에도 사용자의 입력에 바로 반응한다.
- 다른 내용과 함께 5초 넘게 저절로 움직이는 요소에는 멈춤, 정지, 숨김 컨트롤을 둔다.

## 글자

- 비교하는 숫자 열에는 `font-variant-numeric: tabular-nums`를 쓴다.
- 제목에는 `text-wrap: balance`나 `text-wrap: pretty`를 써서 한 글자만 다음 줄로 넘어가지 않게 한다.
- 말줄임은 `...` 대신 `…`를 쓴다. 로딩 문구도 `불러오는 중…`처럼 `…`로 끝낸다.
- 숫자와 단위, 단축키는 줄바꿈되지 않게 붙인다. 예: `10&nbsp;MB`

## 긴 내용과 빈 내용

- 글이 들어가는 영역은 긴 내용을 견딘다. 말줄임, 줄 수 제한, 줄바꿈 가운데 하나를 쓴다. flex 자식에는 `min-width: 0`을 준다.
- 빈 문자열과 빈 목록에서도 화면이 깨지지 않게 빈 상태를 만든다. 빈 상태에는 할 수 있는 다음 동작과 그 버튼을 둔다.
- 사용자가 쓰는 내용은 짧은 것, 보통, 아주 긴 것을 모두 넣어 본다.

## 이미지

- `img`에는 `width`와 `height`를 정해 불러오는 동안 배치가 밀리지 않게 한다.
- 첫 화면 아래 이미지는 `loading="lazy"`, 첫 화면의 중요한 이미지는 `fetchpriority="high"`를 쓴다.

## 성능

- 50개가 넘는 목록은 가상 스크롤이나 `content-visibility: auto`를 쓴다. 표(`table`)의 행에는 `content-visibility`가 적용되지 않으므로, 표는 `table`을 그대로 쓰고 페이지 나누기나 가상 스크롤로 줄인다.
- 그리는 중에 배치 값(`getBoundingClientRect`, `offsetHeight` 등)을 읽지 않는다.
- 중요한 글꼴은 미리 불러오고 `font-display: swap`을 쓴다.
- 움직이는 GIF 대신 압축한 동영상을 쓰고 정지 이미지를 함께 둔다.

## 탐색과 상태

- 필터, 탭, 페이지, 펼친 패널 같은 화면 상태는 URL에 담는다.
- 링크는 `a`로 만들어 새 탭 열기가 되게 한다.
- 지우기처럼 되돌릴 수 없는 동작은 확인을 받거나 되돌릴 시간을 준다. 바로 실행하지 않는다.

## 터치와 조작

- 끌기, 밀기, 집기 같은 동작에는 누르기와 키보드로 하는 방법을 함께 둔다.
- 대화상자, 서랍, 시트 안에는 `overscroll-behavior: contain`을 둔다.
- 휴대폰에서는 자동 포커스를 쓰지 않는다.

## 배치

- 화면 끝까지 채우는 배치는 `env(safe-area-inset-*)`로 노치를 피한다.
- 원하지 않는 스크롤 막대가 생기지 않게 넘치는 내용을 고친다.
- 배치는 스크립트로 재지 않고 flex와 grid로 만든다.
- 확대를 막는 viewport 설정(`user-scalable=no`, `maximum-scale=1`)을 쓰지 않는다.

## 다크 모드

- 다크 모드에서는 `html`에 `color-scheme: dark`를 둔다.
- `<meta name="theme-color">`를 페이지 배경과 맞춘다.

## 날짜와 숫자 형식

- 날짜와 시각은 `Intl.DateTimeFormat`, 숫자와 금액은 `Intl.NumberFormat`으로 만든다. 형식을 직접 쓰지 않는다. 한국어 화면은 `ko-KR`로 만든다. 날짜는 `2026. 10. 7.`, 시각은 `오전 10:20`처럼 한글 맞춤법의 형식이 된다.
- 브랜드 이름과 코드는 `translate="no"`로 자동 번역에서 뺀다.

## 상호작용 상태

- 버튼과 링크는 가리켰을 때 모양이 바뀐다.
- 가리키기, 누르기, 포커스 상태는 기본 상태보다 대비가 크다.

## 화면 글

- 말투는 [PRODUCT.md의 말투](../PRODUCT.md#말투)를 따른다. 한 제품 안에서는 한 문체로 쓴다.
- 사용자가 다른 서비스에서 흔히 보는 말을 쓴다. 다듬은 말보다 이미 굳은 외래어를 쓰고, 같은 뜻에는 같은 말을 쓴다. 말을 고를 때는 [TERMS.md](../TERMS.md)를 먼저 찾고, 없으면 쓰는 디자인 시스템, [KRDS](https://www.krds.go.kr/) 순서로 확인한다.
- 서버, API, 토큰, 세션, 캐시, HTTP 상태 코드, 예외 이름을 화면에 쓰지 않는다. 사용자가 겪는 결과로 쓴다. 예: `로그인 시간이 지났습니다. 다시 로그인하세요.`
- 오류 코드는 지원 문의에 필요할 때만 본문 아래에 `오류 코드: 1234`처럼 쓴다. 제목에 넣지 않는다.
- 오류 메시지에는 무엇이 잘못됐는지와 고칠 방법이나 다음 동작을 쓴다. 사용자를 탓하는 말(`잘못된`, `올바르지 않은 입력`)을 쓰지 않는다.
- 버튼과 메뉴에는 문장 어미 없이 일어날 일을 쓴다. 예: `확인` 대신 `메모 삭제`
- 확인 대화상자의 실행 버튼은 동작 이름으로 쓴다. 예: `삭제`, `보내기`. `확인`은 알리기만 하는 창에 쓴다.
- 창만 닫는 버튼은 `닫기`, 진행 중인 작업을 멈추는 버튼은 `취소`로 쓴다. 창만 닫는 버튼을 `취소`로 쓰면 작업이 취소된다고 읽힌다.
- `예`와 `아니요` 대신 선택지만 읽어도 뜻을 알 수 있게 쓴다. 예: `동의함`, `동의 안 함`
- 겁을 주거나 재촉해서 행동을 이끌지 않는다. 예: `지금 안 하면 손해예요`
- 지나친 높임(`-하실 수 있으십니다`)과 번역투(`계속하기를 원하십니까?`)를 쓰지 않는다. 사용자가 한 일은 능동문으로 쓴다.
- 값 뒤에 붙는 조사는 코드에서 받침에 맞게 고른다. 고를 수 없으면 `을(를)`처럼 쓴다.
- 개수는 숫자로 쓴다. 예: `배포 8건`
