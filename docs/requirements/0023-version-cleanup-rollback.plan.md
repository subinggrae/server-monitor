# 0023. 오래된 버전 자동 정리와 직전 버전으로 되돌리는 명령 구현 계획

- 요구사항: [0023. 오래된 버전 자동 정리와 직전 버전으로 되돌리는 명령](0023-version-cleanup-rollback.md)
- 상태: 승인

## 접근 방법

운영 명령(`infrastructure/monitoring-server.sh`)이 설치 폴더에 **버전 기록 파일** `monitoring-versions`를 두고, `start`가 성공할 때마다 지금 버전과 직전 버전을 적는다. 정리와 `rollback`은 모두 이 기록을 기준으로 한다.

직전 버전은 다음과 같이 정한다.

- **기록이 있을 때**: 기록의 지금 버전(마지막으로 `start`가 성공한 버전)이 새로 띄울 버전과 다르면 그 버전이고, 같으면 기록의 직전 버전이다. 같은 버전을 다시 띄우면 직전 버전이 그대로다(요구사항 S3).
- **기록이 없을 때**: `start`를 시작할 때 떠 있던(멈춘 것 포함) 컨테이너의 버전 label이 새로 띄울 버전과 다르면 그 버전이다. 이 기능 전 묶음으로 띄운 서버를 위한 것이다.

떠 있던 label은 띄우기에 실패한 버전일 수 있어 기록이 있으면 보지 않는다. 새 버전을 띄웠다가 준비 확인에서 실패하면 컨테이너는 그 버전이지만 기록은 바뀌지 않으므로, 그 버전이나 다른 새 버전, 또는 성공했던 버전을 다시 띄워도 직전 버전은 마지막으로 성공한 버전이다(요구사항 S5, S10). 리뷰에서 label을 먼저 보면 실패한 버전 때문에 마지막으로 정상이던 버전이 지워지는 것을 찾아 이렇게 바꿨다.

`rollback`은 지금 버전(떠 있는 컨테이너의 label, 없으면 기록의 지금 버전)의 직전 버전을 기록으로만 찾는다. 찾은 버전의 묶음 폴더에 있는 `monitoring-server.sh start`를 실행한다. 되돌릴 때도 그 버전의 검사와 띄우기를 그대로 거치고, 기록과 정리도 그 `start`가 한다. 그 `start`가 끝난 뒤 떠 있는 버전이 찾은 버전일 때만 되돌렸다고 알린다(요구사항 S11).

검토했지만 고르지 않은 방법은 다음과 같다.

- **이미지의 커밋 시각 label로 순서를 정함**: 기록 파일이 필요 없다. 하지만 되돌린 뒤에는 커밋 시각이 가장 최근인 버전이 직전 버전이 아니게 된다. B로 되돌린 뒤 정리하면 C가 지워진다.
- **묶음 폴더마다 기록을 둠**: 폴더를 지우면 기록도 사라지고, 어느 폴더의 기록이 맞는지 다시 정해야 한다.
- **Docker 이미지 생성 시각**: 빌드 캐시 때문에 버전마다 같을 수 있다(Dockerfile의 commit-time label 주석).

## 바뀌는 부분

- **`infrastructure/monitoring-server.sh`**
  - `start` 시작 때 떠 있던 버전을 읽어 두고, 준비 확인이 끝나면 버전 기록을 쓰고 정리한다.
  - `rollback` 작업과 사용법 줄을 더한다.
  - 머리 주석의 "오래된 버전 정리는 운영 가이드의 절차로 한다"를 고친다.
- **`infrastructure/tests/monitoring-server.test.sh`**
  - 가짜 docker에 이미지 목록(`image ls`, `image rm`, 버전별 `image inspect`)을 더한다.
  - 다른 버전의 묶음 폴더를 만드는 도우미와 정리·되돌리기 시험을 더한다.
  - 알 수 없는 작업 시험의 작업 목록에 `rollback`을 더한다.
- **`docs/OPERATIONS.md`**
  - 6단계의 폴더 그림에 `monitoring-versions`를 더한다.
  - 새 버전으로 갱신의 손으로 지우는 절차를 자동 정리 설명으로 바꾸고, 기록이 없을 때(S6) 손으로 지우는 방법만 남긴다.
  - 이전 버전으로 되돌리기를 `rollback`으로 바꾸고, 두 단계 전 버전은 그 폴더에서 `start`한다고 적는다.

### 데이터 모델 변경

설치 폴더에 버전 기록 파일 `monitoring-versions`를 새로 둔다. 운영 명령만 읽고 쓴다.

```text
# sh monitoring-server.sh start가 쓰는 파일입니다. 고치지 마세요.
current=<지금 버전>
previous=<직전 버전, 없으면 빈 값>
```

버전 값은 Docker 태그 형식(`[A-Za-z0-9_][A-Za-z0-9_.-]*`, 128자 이하)만 받는다. 형식이 틀린 값은 없는 값으로 본다.

### 계약 변경

해당 없음. HTTP SD, webhook, compose 파일, 이미지는 바뀌지 않는다.

## 위험과 되돌리기

- **지우면 안 되는 버전을 지움**: 지우는 것은 묶음 폴더와 이미지뿐이고 기록, `.env`, token, CA 인증서 파일은 건드리지 않는다. 잘못 지웠으면 빌드 PC의 `dist\`에서 그 묶음을 다시 옮겨 `start`한다. 시험으로 S2, S3, 실패 뒤 다시 띄우기, 되돌린 뒤 정리를 확인한다.
- **기록 파일을 쓰지 못함**: 모니터링 시스템은 이미 떠 있으므로 실패로 끝내지 않고 경고한다. 다음 `start`는 떠 있는 컨테이너의 label로 직전 버전을 정하므로 정리는 맞게 된다. `rollback`만 직전 버전을 찾지 못할 수 있다.
- **이 기능을 되돌림**: 이 기능 전 묶음 폴더에서 `start`하면 그 버전으로 돌아간다. 기록 파일은 남지만 그 버전은 읽지 않는다.

### 보안 위협

- 바뀌는 신뢰 경계와 데이터 흐름: 운영 명령이 설치 폴더의 목록, 버전 기록 파일, 다른 묶음 폴더의 `compose.yml`, Docker 이미지 목록을 읽고, 그 결과로 폴더와 이미지를 지운다. 이 값들은 운영자나 다른 프로그램이 바꿀 수 있는 입력으로 본다. [ARCHITECTURE.md의 지켜야 할 경계](../ARCHITECTURE.md#지켜야-할-경계)는 바뀌지 않는다.
- 잘못될 수 있는 것과 막는 방법:
  - 링크를 따라가 설치 폴더 밖을 지우거나 기록 파일 대신 다른 파일에 씀(CWE-59) → 지울 폴더가 링크면 건너뛴다. 폴더 안에서 만난 링크는 링크 파일만 지운다. 기록 파일이 링크면 읽지도 쓰지도 않고 경고한다. 기록은 같은 폴더의 임시 파일에 쓴 뒤 이름을 바꾼다.
  - 검사한 뒤 지우기 전에 폴더나 그 안의 폴더를 링크로 바꿔치기함(CWE-367) → `rm -rf <경로>`를 쓰지 않는다. 운영 명령이 폴더마다 `cd`로 들어가 `pwd -P`가 들어가려던 실제 위치와 같은지 확인하고, 그 안에서는 이름만으로 `rm -f --`와 `rmdir`을 실행한다. 셸의 현재 폴더는 들어간 뒤 경로가 바뀌어도 그대로이므로 확인과 지우기 사이에 틈이 없다. 위치가 다르면 그 폴더를 지우지 않고 S8처럼 경고한다. 지우기는 GNU와 BusyBox `rm`의 재귀 구현에 기대지 않는다(사람 확인: 2026-11-17).
  - 기록 파일이나 `compose.yml`의 버전 값으로 다른 경로를 만듦(CWE-22) → 버전 값은 Docker 태그 형식만 받는다. `rollback`의 대상 폴더는 `설치 폴더/monitoring-system-<버전>`으로만 만들고, 그 폴더의 `compose.yml` 버전이 기록과 같은지 확인한다.
  - 지울 대상을 넓게 고름 → 설치 폴더 바로 아래에서 이름이 `monitoring-system-`으로 시작하고, 링크가 아닌 폴더이며, 그 안의 `compose.yml`에서 읽은 버전이 형식에 맞는 것만 묶음으로 본다. 이미지는 `monitoring-system-prometheus`, `monitoring-system-alertmanager`, `monitoring-system-blackbox-exporter` 저장소의 형식에 맞는 태그만 지운다.
  - 값이 명령으로 실행됨(CWE-78) → 버전 값을 `eval`하지 않고, 형식 검사를 통과한 값만 따옴표로 감싸 인자로 넘긴다.
- 받아들이는 위험: 없음

## 진행 중 발견

- 미리 옮겨 두고 아직 띄우지 않은 묶음 폴더도 지금 버전이나 직전 버전이 아니면 지워진다. 요구사항의 "나머지 버전을 지운다"대로이고, 띄운 적이 없는 버전은 앞뒤를 알 수 없기 때문이다. 시험에서 v3을 미리 옮겨 둔 채 v2를 띄우자 v3이 지워졌다. 그래서 시험은 띄우기 직전에 묶음을 옮기게 고쳤고, 운영 가이드에 새 묶음은 띄우기 직전에 옮긴다고 적었다.
- 지울 폴더 안쪽의 위치 확인(`pwd -P`)은 확인과 지우기 사이에 바꿔치기가 일어나야만 동작이 달라져 자동 시험으로 재현할 수 없다. 링크 검사와 위치 확인을 함께 지운 사본에서 설치 폴더 밖의 파일이 지워져 시험이 실패하는 것으로 확인했다. 검사를 하나씩 지운 사본 6개(묶음 폴더 링크, 안쪽 링크, 안쪽 링크와 위치, 버전 형식, 기록 파일 링크, 이름과 compose 버전 비교)에서 모두 해당 시험이 실패했다.

## 남길 결정

없음. 버전 기록 파일의 형식과 직전 버전을 정하는 규칙은 운영 명령의 주석과 운영 가이드에 남긴다. 운영 명령만 읽고 쓰는 파일이라 다른 모듈이나 외부 클라이언트가 기대지 않는다.
