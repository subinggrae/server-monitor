# 0002. E2E 테스트와 화면 검사 도구

- 상태: 구현됨
- 작성일: 2026-10-14
- 관련: 없음

## 배경

지금 테스트는 Backend 단위 테스트와 Frontend 컴포넌트 테스트뿐이다. 컴포넌트 테스트는 fetch를 대역(`fakeApi`)으로 바꾸므로, 화면, Manager API, Manager Database, Prometheus를 함께 거치는 흐름은 사람이 띄워서 손으로 확인한다. 예를 들어 [0001](0001-per-target-scrape-interval.md)의 C9는 수동 확인이었다.

화면 점검도 끝낼 수 없다. [REVIEW.md의 화면 점검](../design/REVIEW.md#화면-점검)은 [DESIGN.md](../design/DESIGN.md) 개요의 화면 검사 도구를 기준 폭마다 실행하라고 하고, 도구를 정하지 않았으면 화면 점검을 마친 것으로 보지 않는다. 그런데 DESIGN.md에는 화면 검사 도구와 기준 폭이 모두 정해지지 않았다.

## 목표

- 개발자가 명령 하나로 핵심 사용자 흐름을 실제 브라우저에서 끝까지 확인한다. 흐름은 화면부터 Manager Database와 Prometheus까지 실제로 띄운 환경을 거친다.
- 개발자가 명령 하나로 기준 폭마다 모든 화면의 접근성 위반과 넘침을 검사한다. 성능은 별도 명령으로 검사한다.
- 화면 검사 도구, 명령, 기준 폭을 DESIGN.md 개요에 적어 화면 점검을 끝낼 수 있게 한다.
- 도구는 다음으로 정했다(사람 확인: 2026-10-14).
  - E2E: Playwright(Apache-2.0)
  - 접근성과 넘침: Playwright에 axe-core를 붙인 검사. axe-core는 MPL-2.0이라 [LICENSES.md의 분류](../LICENSES.md#분류)에서 조건 확인이다. 개발 도구로만 쓰고 배포하는 화면에 넣지 않아 소스 공개 조건이 생기지 않으므로 쓰기로 했다.
  - 성능: Lighthouse(Apache-2.0, 내부에서 axe-core를 쓴다)
  - 흔한 기본값: 도구 없이 [REVIEW.md의 코드 점검](../design/REVIEW.md#코드-점검) 목록을 코드 검색으로 확인한다. Impeccable은 함께 설치되는 실행 파일 패키지의 라이선스를 레지스트리에서 확인하지 못했고 Node.js 22.18 이상이 필요해 쓰지 않는다.

## 하지 않는 것

- E2E와 화면 검사를 전체 검증(`npm run check`)에 넣는 것. 브라우저와 서버가 필요한 검사는 따로 실행한다([DEVELOPMENT.md의 명령 이름](../DEVELOPMENT.md#명령-이름)).
- CI를 붙이는 것
- 시각 체계(스타일, 글꼴, 색, 간격 등)를 정하는 것. DESIGN.md에서 화면 검사 도구와 기준 폭만 정한다.
- 화면 검사가 처음 찾은 기존 위반을 이번에 모두 고치는 것. 목록으로 보고하고 처리 방법을 따로 정한다.
- Telegram 실제 전송을 E2E로 확인하는 것. 외부 서비스라 결과가 실행마다 달라진다.
- 스크린샷을 비교하는 시각 회귀 테스트

## 사용자 경험

사용자는 이 저장소의 개발자와 AI 에이전트다.

1. 개발자가 전체 실행 환경(`docker compose --profile local-db up -d --build`, http://localhost:8081)을 띄운다. 다른 주소에 실행하려면 환경 변수로 화면 주소를 바꾼다.
2. E2E 명령을 실행하면 핵심 흐름을 브라우저로 끝까지 수행하고, 종료 코드로 결과를 알린다. 실패하면 실패한 단계의 스크린샷과 실행 기록이 Git이 무시하는 폴더에 남는다.
3. 화면을 바꾼 뒤 화면 검사 명령을 실행하면 기준 폭마다 모든 화면을 열어 접근성 위반과 가로 넘침을 찾고, 위반 목록과 종료 코드로 결과를 알린다.
4. 성능은 성능 검사 명령으로 화면 주소의 점수와 주요 지표를 확인한다.

## 동작

### 정상 동작

- **S1. E2E 실행**
  - 상황: 전체 실행 환경이 떠 있다.
  - 행동: 개발자가 E2E 명령을 실행한다.
  - 결과: 다음 두 흐름을 브라우저로 끝까지 수행하고, 모두 통과하면 0으로 끝난다. 테스트가 만든 Check는 끝날 때 지운다.
    - Check를 등록하고 목록과 상세에서 확인한 뒤 삭제한다.
    - 등록한 Check의 수집 결과가 대시보드에 상태로 보인다. Prometheus가 HTTP SD로 대상을 가져가 수집한 결과다.
- **S2. 화면 검사**
  - 상황: 전체 실행 환경이 떠 있다.
  - 행동: 개발자가 화면 검사 명령을 실행한다.
  - 결과: 기준 폭(1280×800, 1920×1080)마다 모든 라우트의 화면(목록, 상세, 빈 상태 포함)을 열어 WCAG 2.2 AA 수준의 접근성 위반과 가로 넘침을 검사한다. 위반이 없으면 0으로 끝난다.
- **S3. 성능 검사**
  - 상황: 전체 실행 환경이 떠 있다.
  - 행동: 개발자가 성능 검사 명령에 화면 주소를 넣어 실행한다.
  - 결과: 데스크톱 기준의 성능 점수와 주요 지표(LCP, CLS, TBT)를 보고한다.

### 예외 동작

- **S4. 환경이 떠 있지 않음**
  - 상황: 전체 실행 환경이 떠 있지 않다.
  - 행동: E2E나 화면 검사 명령을 실행한다.
  - 결과: 화면 주소에 접속하지 못했다고 알리고, 테스트 타임아웃까지 기다리지 않고 0이 아닌 코드로 끝난다.
- **S5. 흐름이 깨짐**
  - 상황: 화면이나 API가 바뀌어 핵심 흐름의 한 단계가 실패한다.
  - 행동: E2E 명령을 실행한다.
  - 결과: 실패한 단계 이름과 함께 0이 아닌 코드로 끝나고, 그 단계의 스크린샷과 실행 기록이 남는다.
- **S6. 이전 실행이 남긴 데이터**
  - 상황: 이전 실행이 중간에 멈춰 테스트 데이터가 남았다.
  - 행동: E2E 명령을 다시 실행한다.
  - 결과: 남은 데이터 때문에 실패하지 않는다. 사람이 만든 데이터는 지우지 않는다.
- **S7. 접근성 위반이 생김**
  - 상황: 화면에 라벨이 없는 입력 칸처럼 접근성 위반이 생겼다.
  - 행동: 화면 검사 명령을 실행한다.
  - 결과: 위반한 규칙, 화면 주소, 기준 폭, 요소를 보이고 0이 아닌 코드로 끝난다.

### 보안

- 접근 권한: 개발 PC에서 띄운 환경에만 접속한다. 화면 주소의 기본값은 `localhost`이고, 운영 주소에는 실행하지 않는다.
- 외부 입력: 없음
- 민감한 정보: 테스트는 비밀값 파일을 읽지 않는다. 스크린샷과 실행 기록에 비밀값이 담기지 않는다. 화면은 SNMP community와 Bot Token을 보이지 않는다.
- 남길 보안 이벤트: 없음

### 바뀌지 않는 것

- `npm run check`가 실행하는 검사와 그 시간
- 기존 단위 테스트와 컴포넌트 테스트
- 애플리케이션 코드와 런타임 의존성
