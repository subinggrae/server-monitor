# 0021. 이전 버전에서 옮기는 처리와 안내를 걷어냄 구현 계획

- 요구사항: [0021. 이전 버전에서 옮기는 처리와 안내를 걷어냄](0021-remove-legacy-migration.md)
- 상태: 진행 중

## 접근 방법

운영 명령에서 이전 방식 전용 함수와 그 호출만 지우고, 남는 확인의 코드와 안내 문구는 건드리지 않는다. 묶음 폴더에 실제 `.env`가 있을 때의 두 갈래 안내는 하나로 합친다(S4). 운영 가이드는 이전 버전 전용 절과 문장만 지우고, 새 버전끼리 갱신하고 되돌리는 절차는 남긴다.

시험은 먼저 바꾼다. 다음 두 가지를 새 기대로 고친 뒤, 지금 운영 명령에서 실패하는지 본다.

- 옛 묶음 폴더에 `.env`가 있어도 무시하는지(S1, S3)
- 묶음 폴더에 실제 `.env`만 있을 때 하나로 합친 안내를 보이는지(S4)

검토했지만 고르지 않은 방법은 다음과 같다.

- 묶음 폴더의 `.env` 확인(`check_env_location`)을 통째로 지움: 편집기가 링크를 실제 파일로 바꿔 저장하는 일은 새 버전에서도 생긴다. 그러면 운영자가 고친 값이 쓰이지 않는다. 그래서 확인은 남기고 안내만 하나로 합친다.

## 바뀌는 부분

| 위치 | 변경 |
|---|---|
| `infrastructure/monitoring-server.sh` | 아래 운영 명령 변경 |
| `infrastructure/tests/monitoring-server.test.sh` | 이전 방식 전용 시험 다섯 개를 옛 묶음 폴더의 `.env`를 무시하는 시험과 합친 안내 시험으로 바꾼다 |
| `docs/OPERATIONS.md` | 아래 운영 가이드 변경 |
| `docs/requirements/0021-remove-legacy-migration.md` | 완료 기준 확인 결과 |

운영 명령 변경은 다음과 같다.

- `previous_env`를 지우고, `check_env`와 `cmd_install`에서 그 호출과 안내를 지운다.
- `check_env_location`의 마지막 안내(`sudo mv`)를 앞의 안내와 합친다.
- 머리 주석과 `running_setting` 주석의 이전 버전 문장을 고친다.

운영 가이드 변경은 다음과 같다. 지운 절로 가는 링크도 고친다.

- "설정 파일을 설치 폴더로 옮기기", "운영 명령이 없던 묶음에서 갱신" 절
- 새 버전으로 갱신 절의 이전 버전 문장 두 개
- 이전 버전으로 되돌리기 절의 예전 묶음 문장과 예전 버전 문단
- 문제 해결 표에서 이전 방식만 다루는 행. `token 파일이 없습니다` 행의 예전 안내도 지운다

### 데이터 모델 변경

해당 없음

### 계약 변경

해당 없음. 관리자 서버와의 계약과 설치 폴더 구조는 바뀌지 않는다.

## 위험과 되돌리기

- 남겨야 할 확인(B)을 함께 지움: `check_env`의 "떠 있는데 설정 파일이 없음" 안내와 `check_token`은 그대로 두고, 그 시험이 계속 통과하는지 본다.
- 묶음 폴더의 `.env` 확인이 약해짐: 합친 뒤에도 실제 파일과 다른 곳을 가리키는 링크에서 멈추는지 시험으로 본다.
- 되돌리기: 커밋을 되돌린다. 서버 상태는 바꾸지 않는 변경이라 되돌릴 데이터가 없다.

### 보안 위협

- 바뀌는 신뢰 경계와 데이터 흐름: 없음. 운영 명령이 읽는 설정 파일이 설치 폴더의 `.env` 하나로 줄어든다.
- 잘못될 수 있는 것과 막는 방법: 링크를 따라 다른 파일을 읽거나 쓰는 것(CWE-59) → 설치 폴더 `.env`의 링크 거부와 묶음 폴더 `.env`의 링크 확인을 그대로 두고, 기존 시험으로 확인한다.
- 받아들이는 위험: 없음
