# 0021. 이전 버전에서 옮기는 처리와 안내를 걷어냄

- 상태: 구현됨
- 작성일: 2026-11-16
- 관련: [#58](https://github.com/subinggrae/server-monitor/issues/58), [0011](0011-core-ops-script.md), [0017](0017-core-shared-env.md), [0020](0020-rename-monitoring-system.md)

## 배경

운영 명령(`monitoring-server.sh`)과 운영 가이드에는 이전 버전의 서버를 새 버전으로 옮기기 위한 처리가 남아 있다.

- 설정 파일을 묶음 폴더에 두던 버전([요구사항 0017](0017-core-shared-env.md) 전)
  - 운영 명령은 떠 있는 버전의 묶음 폴더나 옛 이름 묶음 폴더(`monitoring-core-<버전>`)에서 `.env`를 찾는다.
  - 찾으면 설치 폴더로 복사하는 명령을 보이고 멈춘다.
  - 묶음 폴더에 실제 `.env` 파일만 있으면 설치 폴더로 옮기는 명령을 보인다.
- 운영 명령이 없던 묶음: token을 묶음 폴더 안에 두던 서버를 옮기는 절차가 운영 가이드에 있다.
- 서버에서 설정 값을 바꿀 수 없던 예전 버전이나 `templates/`가 없는 예전 묶음으로 되돌릴 때의 주의가 운영 가이드에 있다.

[요구사항 0020](0020-rename-monitoring-system.md)으로 이름이 바뀐 뒤에는 이전 버전의 묶음에서 갱신할 수 없다. 정식으로 운영하는 서버도 없다. 기존 배포는 모두 지우고 새 버전을 새로 배포한다(사람 확인: 2026-11-16). 그래서 위 처리는 더는 쓰이지 않는다. 오히려 운영 가이드와 운영 명령을 읽기 어렵게 만든다.

## 목표

- 운영 명령은 이전 방식의 묶음 폴더에서 설정 파일을 찾거나, 복사·이동 명령을 보이지 않는다.
- 운영 가이드에서 이전 버전에서 옮기거나 이전 버전으로 되돌리는 절차와 문장, 문제 해결 표의 해당 행을 지운다.
- 이전 버전 전용 처리를 확인하던 운영 명령 시험을 지운다.

## 하지 않는 것

- 이미 떠 있는 모니터링 시스템이 있을 때의 확인을 지우는 것. 다음은 모두 남긴다(사람 확인: 2026-11-16).
  - 보관 기간·용량을 줄이면 묻기
  - 떠 있는데 설정 파일이나 token 파일이 없을 때 새로 만들지 말라고 안내하기
  - 새 버전끼리 되돌리는 운영 가이드 절차
- 새로 배포할 때도 필요한 확인을 바꾸는 것. 묶음 체크섬, 설정 값 검사, token·CA 인증서·네트워크 확인, 링크 거부, 정상 상태 확인이 그렇다.
- 설치 폴더에 `.env`, `secrets/`, `certs/`를 두고 묶음 폴더에 `../.env` 링크를 두는 구조([요구사항 0017](0017-core-shared-env.md))
- 지난 요구사항과 ADR의 글

## 사용자 경험

운영자는 새로 설치하거나 새 버전끼리 갱신할 때만 운영 명령을 쓴다. 바뀌는 것은 다음 두 가지뿐이다.

1. 설치 폴더에 설정 파일이 없을 때 이전 묶음 폴더의 파일을 찾아 복사하라고 하지 않는다. 지금처럼 `install`을 안내한다. 떠 있는 모니터링 시스템이 있으면 쓰던 파일을 복사하라고 안내한다.
2. 묶음 폴더에 실제 `.env` 파일이 있으면 늘 같은 안내로 멈춘다. 설정은 설치 폴더의 `.env`에 둔다는 안내다.

## 동작

### 정상 동작

- **S1. 처음 설치**
  - 상황: 설치 폴더에 설정 파일이 없고 모니터링 시스템도 없다. 설치 폴더에 옛 이름의 묶음 폴더와 그 안의 `.env`가 남아 있어도 같다.
  - 행동: 운영자가 `install`을 실행한다.
  - 결과: 관리자 서버 주소를 묻고 설치 폴더에 `.env`를 만든다. 다른 폴더의 `.env`는 보지 않는다. `start`를 먼저 실행하면 `install`을 먼저 실행하라고 안내하고 멈춘다.

- **S2. 새 버전끼리 갱신**
  - 상황: 이 변경 뒤의 버전이 떠 있고 설치 폴더에 `.env`가 있다.
  - 행동: 운영자가 새 묶음 폴더에서 `start`를 실행한다.
  - 결과: 지금과 같이 새 버전으로 바뀐다.

### 예외 동작

- **S3. 떠 있는데 설정 파일이 없음**
  - 상황: 모니터링 시스템이 있고(떠 있거나 멈춰 있음) 설치 폴더에 `.env`가 없다.
  - 행동: 운영자가 `start`나 `render`를 실행한다.
  - 결과: 쓰던 `.env`를 설치 폴더로 복사하라는 지금의 안내를 보이고 멈춘다. 다른 폴더의 파일 경로는 보이지 않는다. 컨테이너와 펼친 설정은 바꾸지 않는다.

- **S4. 묶음 폴더에 실제 설정 파일이 있음**
  - 상황: 묶음 폴더의 `.env`가 운영 명령이 만드는 `../.env` 링크가 아니다. 실제 파일이거나 다른 곳을 가리키는 링크다. 설치 폴더에 `.env`가 있든 없든 같다.
  - 행동: 운영자가 `install`, `render`, `start`를 실행한다.
  - 결과: 묶음 폴더의 설정 파일은 쓰지 않는다는 안내를 보이고 멈춘다. 안내에는 설정은 설치 폴더의 `.env`에 둔다는 것, 고친 값을 그 파일에 옮겨 적은 뒤(없으면 새로 만들어) 묶음 폴더의 파일을 지우라는 것이 들어 있다. 운영 명령은 파일을 옮기거나 지우지 않는다.

- **S5. 설치 폴더의 설정 파일이 링크**
  - 상황: 설치 폴더의 `.env`가 링크다.
  - 행동: 운영자가 `install`, `render`, `start`를 실행한다.
  - 결과: 지금처럼 링크를 따라가지 않고 멈춘다(CWE-59).

### 보안

- 접근 권한: 바뀌지 않는다.
- 외부 입력: 설치 폴더와 묶음 폴더의 `.env`. 운영 명령이 읽는 곳이 설치 폴더의 `.env` 하나로 줄어든다. 링크를 따라가지 않는 검사는 그대로다.
- 민감한 정보: webhook token. 위치와 권한, 새로 만들지 않는 조건은 바뀌지 않는다.
- 남길 보안 이벤트: 없음

### 바뀌지 않는 것

- 하지 않는 것에 적은 확인과 그 안내 문구(S3의 안내 포함)
- 운영 명령의 작업(`install`, `render`, `start`, `status`)
- 설치 폴더의 `.env`를 셸로 실행하지 않고 읽는 것
