# 0017. 설치 폴더 하나의 코어 설정 파일

- 상태: 구현됨
- 작성일: 2026-11-11
- 관련: [0011](0011-core-ops-script.md), [0013](0013-core-env-settings.md), [0015](0015-core-minimal-image.md)

## 배경

코어 설정 파일(`.env`)은 버전마다 묶음 폴더 안에 있다. 그래서 새 버전으로 갱신할 때마다 이전 묶음 폴더의 `.env`를 새 폴더로 복사해야 한다([운영 가이드의 새 버전으로 갱신](../OPERATIONS.md#새-버전으로-갱신)). 복사를 잊으면 `start`가 멈춘다. 그때 `install`을 실행하면 바꿔 둔 값이 기본값으로 돌아간다. 사람이 2026-11-11에 이 복사가 번거롭다고 하고, 설정 파일을 설치 폴더에 하나만 두어 모든 버전이 함께 읽게 하기로 했다.

token(`secrets/`)과 CA 인증서 파일(`certs/`)은 이미 설치 폴더에 두므로 버전이 바뀌어도 그대로 쓴다. 설정 파일도 같은 자리에 두면 갱신할 때 옮길 파일이 없어진다. 운영 명령에 파일을 복사하는 기능을 더하지 않아도 되므로, 운영 명령을 최소 기능으로 두기로 한 [0015](0015-core-minimal-image.md)와도 맞다.

## 목표

- 묶음에서 코어 설정 파일은 설치 폴더의 `.env` 하나다. 모든 버전의 운영 명령이 이 파일을 읽는다.
- `install`은 설치 폴더에 `.env`를 만든다.
- 새 버전으로 갱신할 때 설정 파일을 복사하는 단계가 없다. 새 묶음 폴더를 옮기고 `start`만 실행한다.
- 묶음 폴더에서 운영 가이드의 `docker compose` 명령(멈추기, 로그 보기, token 바꾸기, 운영 명령 없이 실행)을 지금처럼 그대로 쓸 수 있고, 이 명령도 설치 폴더의 `.env`에 적은 포트와 token 폴더를 쓴다.
- 이미 설치한 서버는 한 번만 이전 묶음 폴더의 `.env`를 설치 폴더로 옮기면 된다.

## 하지 않는 것

- 저장소에서 띄우는 개발용 코어. `infrastructure/.env`를 그대로 쓴다.
- 버전마다 다른 설정을 두는 것. 이전 버전으로 되돌려도 설정은 되돌아가지 않는다. 다만 이 변경 전의 묶음으로 되돌리면, 그 묶음은 자기 폴더의 `.env`를 읽는다.
- `.env`를 설치 폴더로 자동으로 옮기거나 복사하는 기능. 운영자가 한 번 옮긴다.
- 설정 값의 이름, 기본값, 허용 범위, 검사 규칙

## 사용자 경험

처음 설치하는 운영자:

1. 설치 폴더에 묶음 폴더와 CA 인증서 파일을 둔다.
2. 묶음 폴더에서 `sudo sh core-server.sh install`을 실행하고 관리자 서버 주소를 넣는다. 설치 폴더에 `.env`와 `secrets/`가 생긴다.
3. 필요하면 설치 폴더의 `.env`를 고치고 `sudo sh core-server.sh start`를 실행한다.

새 버전으로 갱신하는 운영자:

1. 새 묶음 폴더를 설치 폴더에 옮긴다.
2. 새 묶음 폴더에서 `sudo sh core-server.sh start`를 실행한다.

이 변경 전 버전에서 처음 갱신하는 운영자:

1. 새 묶음 폴더에서 `start`를 실행하면, 설치 폴더에 `.env`가 없다며 이전 묶음 폴더의 `.env`를 설치 폴더로 복사하는 명령을 보여 준다.
2. 운영자가 그 명령을 실행하고 `start`를 다시 실행한다.

## 동작

### 정상 동작

- **S1. 처음 설치**
  - 상황: 설치 폴더에 `.env`가 없다.
  - 행동: 운영자가 묶음 폴더에서 `install`을 실행하고 관리자 서버 주소를 넣는다.
  - 결과: 설치 폴더에 `.env`가 생긴다. 묶음 폴더에는 설정 파일이 생기지 않는다.
- **S2. 새 버전으로 갱신**
  - 상황: 설치 폴더에 `.env`가 있고, 이전 버전이 떠 있다.
  - 행동: 운영자가 새 묶음 폴더에서 `start`를 실행한다.
  - 결과: 설치 폴더의 `.env` 값으로 새 버전이 뜬다. 바꿔 둔 포트, 보관 값, token 폴더가 이어진다.
- **S3. 묶음 폴더에서 compose 명령 실행**
  - 상황: 설치 폴더의 `.env`에 Prometheus 포트를 19090으로 적고 `start`로 띄웠다.
  - 행동: 운영자가 묶음 폴더에서 `docker compose up -d --force-recreate alertmanager`나 `docker compose down`을 실행한다.
  - 결과: Compose가 설치 폴더의 `.env` 값(19090, token 폴더)을 쓴다. 기본값으로 돌아가지 않는다.
- **S4. 설정 값 바꾸기**
  - 상황: 코어가 떠 있다.
  - 행동: 운영자가 설치 폴더의 `.env`를 고치고 `start`를 실행한다.
  - 결과: 지금과 같이 값을 검사하고 다시 띄운다. 보관 값을 줄이면 계속할지 묻는다.

### 예외 동작

- **S5. 이전 방식 서버에서 처음 갱신**
  - 상황: 설치 폴더에 `.env`가 없고, 이전 묶음 폴더에만 `.env`가 있다.
  - 행동: 운영자가 새 묶음 폴더에서 `start`를 실행한다.
  - 결과: 코어를 바꾸지 않고 멈춘다. 이전 묶음 폴더의 `.env`를 설치 폴더로 복사하는 명령을 보여 준다. 운영 명령이 직접 복사하지는 않는다(사람 확인: 2026-11-11).
- **S6. 묶음 폴더에 설정 파일이 남아 있음**
  - 상황: 설치 폴더에 `.env`가 있는데, 지금 묶음 폴더에도 운영자가 둔 별도의 `.env` 파일이 있다.
  - 행동: 운영자가 `start`나 `render`를 실행한다.
  - 결과: 어느 값을 쓰는지 헷갈리지 않도록 코어를 바꾸지 않고 멈춘다. 묶음 폴더의 `.env`를 지우라고 안내한다(사람 확인: 2026-11-11).
- **S7. 설치 폴더 `.env`가 없는 처음 설치에서 `start`**
  - 상황: 설치 폴더와 이전 묶음 폴더 어디에도 `.env`가 없다.
  - 행동: 운영자가 `start`를 실행한다.
  - 결과: 지금처럼 `install`을 먼저 실행하라고 안내하고 멈춘다.
- **S8. 이전 방식 서버에서 `install`**
  - 상황: 설치 폴더에 `.env`가 없고, 이전 묶음 폴더에 쓰던 `.env`가 있다.
  - 행동: 운영자가 새 묶음 폴더에서 `start` 대신 `install`을 실행한다.
  - 결과: 주소를 묻거나 새 `.env`와 token을 만들지 않고 멈춘다. S5처럼 쓰던 파일을 복사하는 명령을 보여 준다. 기본값 `.env`를 새로 만들면 바꿔 둔 값이 사라지기 때문이다(사람 확인: 2026-11-11).

### 보안

- 접근 권한: 지금과 같다. 운영 명령은 `sudo`로 실행한다.
- 외부 입력: 설치 폴더의 `.env` 내용. 지금처럼 셸로 실행하지 않고 값으로만 읽는다.
- 민감한 정보: `.env`에는 비밀값이 없다. token은 지금처럼 `secrets/`에 둔다.
- 남길 보안 이벤트: 없음

### 바뀌지 않는 것

- 설정 값의 이름, 기본값, 허용 범위, 틀린 값의 안내
- token 폴더(`CORE_SECRETS_DIR`)의 상대 경로 기준(묶음 폴더)
- 보관 값을 줄일 때 확인하는 동작, `render`와 `status`의 동작
- 저장소 개발용 코어의 `infrastructure/.env`
