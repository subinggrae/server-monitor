# 0023. 오래된 버전 자동 정리와 직전 버전으로 되돌리는 명령

- 상태: 승인
- 작성일: 2026-11-17
- 관련: [0015](0015-core-minimal-image.md), [0017](0017-core-shared-env.md), [OPERATIONS.md의 새 버전으로 갱신](../OPERATIONS.md#새-버전으로-갱신)

## 배경

새 버전을 배포하면 모니터링 서버에 묶음 폴더(약 96MB)와 이미지 세 개(불러온 상태로 약 327MB)가 버전마다 남는다. 운영 명령(`monitoring-server.sh`)은 이들을 지우지 않는다. 그래서 운영자가 운영 가이드대로 지금 띄운 버전과 직전 버전을 확인한 뒤, 나머지 묶음 폴더와 이미지를 손으로 지워야 한다. 지우지 않으면 갱신할 때마다 디스크를 더 쓴다.

이전 버전으로 되돌릴 때는 운영자가 직전 버전의 묶음 폴더 이름을 찾아 그 폴더에서 `start`를 실행한다. 어느 버전이 직전 버전인지는 운영자가 기억하거나 폴더 목록을 보고 판단해야 한다.

[0015](0015-core-minimal-image.md)는 운영 명령을 최소 기능으로 두면서 오래된 버전을 지우는 일을 운영 명령에서 뺐고, 필요해지면 별도 요구사항으로 더하기로 했다(사람 확인: 2026-11-10). 이번에 정리와 되돌리기를 운영 명령에 더하기로 했다(사람 확인: 2026-11-17).

## 목표

- `start`가 성공하면 운영 명령이 지금 띄운 버전과 직전 버전만 남기고, 나머지 버전의 묶음 폴더와 이미지를 묻지 않고 지운다. 지운 버전은 화면에 보인다(사람 확인: 2026-11-17).
- 남기는 버전은 지금 버전과 직전 버전 두 개로 고정한다(사람 확인: 2026-11-17).
- 직전 버전은 버전 이름의 순서가 아니라, 지금 버전으로 바꾸기 전에 마지막으로 `start`가 성공한 버전이다(사람 확인: 2026-11-17). 그래야 되돌린 뒤에 정리해도 되돌리기 전의 새 버전이 남고, 띄우기에 실패한 버전 때문에 마지막으로 정상이던 버전이 지워지지 않는다.
- 운영자가 새 `rollback` 작업을 실행하면, 폴더 이름을 찾지 않아도 직전 버전으로 되돌린다. 어느 묶음 폴더에서 실행해도 결과가 같다(사람 확인: 2026-11-17).

## 하지 않는 것

- 쌓은 기록(volume), 설치 폴더의 `.env`, token, CA 인증서 파일을 지우는 것
- 남길 버전 수를 `.env`로 바꾸게 하는 것(사람 확인: 2026-11-17)
- `start`가 실패했을 때 운영 명령이 알아서 직전 버전으로 되돌리는 것. 되돌릴지는 운영자가 정하고 `rollback`을 실행한다(사람 확인: 2026-11-17).
- 두 단계 이상 전의 버전으로 되돌리는 명령. 그 버전의 묶음 폴더가 남아 있으면 지금처럼 그 폴더에서 `start`를 실행한다.
- 되돌릴 때 설정을 함께 되돌리는 것. 설정은 지금처럼 설치 폴더의 `.env` 하나를 모든 버전이 함께 쓴다([0017](0017-core-shared-env.md)).
- 감시 대상 서버의 node_exporter 묶음과 이미지, 빌드 PC의 이미지를 정리하는 것
- 설치 폴더에 있는 묶음 폴더가 아닌 파일과 폴더, `monitoring-system-` 밖의 이름을 가진 Docker 이미지를 지우는 것
- 이 기능이 없는 이전 묶음으로 띄운 서버를 위한 처리. 이전 묶음으로 띄운 서버는 없고, `install`만 해 둔 서버가 있다(사람 확인: 2026-11-17). 그 서버에서 새 버전을 처음 띄우면 S6대로 이전 묶음 폴더를 지우지 않고 안내하며, 운영자가 손으로 지운다.

## 사용자 경험

새 버전으로 갱신할 때는 다음 순서를 따른다.

1. 운영자가 새 묶음 폴더를 설치 폴더로 옮긴다.
2. 운영자가 새 폴더에서 `sudo sh monitoring-server.sh start`를 실행한다.
3. 운영 명령이 새 버전을 띄운 뒤, 지금 버전과 직전 버전 밖의 버전을 지우고 지운 버전을 보인다.

문제가 생겨 되돌릴 때는 다음 순서를 따른다.

1. 운영자가 설치 폴더의 아무 묶음 폴더에서 `sudo sh monitoring-server.sh rollback`을 실행한다.
2. 운영 명령이 직전 버전을 찾아 그 버전을 띄우고, 어느 버전에서 어느 버전으로 바꿨는지 보인다.

## 동작

아래 예에서 A, B, C는 이 순서로 배포한 버전이다.

### 정상 동작

- **S1. 처음 띄우기**
  - 상황: 모니터링 시스템을 띄운 적이 없는 서버의 설치 폴더에 묶음 폴더 A만 있다.
  - 행동: 운영자가 A에서 `start`를 실행하고 성공한다.
  - 결과: 아무것도 지우지 않는다. A를 지금 버전으로 기억한다.
- **S2. 새 버전으로 갱신하면 오래된 버전을 지움**
  - 상황: 설치 폴더에 A, B 묶음 폴더가 있고 서버에 두 버전의 이미지가 있다. B가 떠 있고 직전 버전은 A다. 운영자가 C 묶음 폴더를 옮겼다.
  - 행동: 운영자가 C에서 `start`를 실행하고 성공한다.
  - 결과: C가 뜬다. 직전 버전은 B가 된다. A의 묶음 폴더와 A의 이미지 세 개를 지우고, 지운 버전 A를 보인다. B와 C는 남는다.
- **S3. 같은 버전을 다시 띄움**
  - 상황: C가 떠 있고 직전 버전은 B다.
  - 행동: 운영자가 C에서 `start`를 다시 실행하고 성공한다.
  - 결과: 직전 버전은 그대로 B이고, B를 지우지 않는다.
- **S4. 직전 버전으로 되돌리기**
  - 상황: C가 떠 있거나 멈춰 있고, 직전 버전은 B다. B의 묶음 폴더가 남아 있다.
  - 행동: 운영자가 B나 C의 묶음 폴더에서 `rollback`을 실행한다.
  - 결과: 되돌릴지 묻지 않고 B의 `start`와 같은 검사를 거쳐 B를 띄운다. 기록 보관 값을 줄이게 되는 경우의 확인은 `start`처럼 묻는다. 쌓은 기록, 장애 상태, `.env`, token, CA 인증서 파일이 이어진다. `되돌렸습니다: C → B`처럼 바꾼 버전을 보인다. 이제 직전 버전은 C이고, B와 C 모두 남는다. 다시 `rollback`을 실행하면 C로 돌아간다.

### 예외 동작

S8을 뺀 예외 동작에서 운영 명령은 무엇이 잘못됐는지와 고치는 방법을 한국어로 보이고 실패로 끝난다.

- **S5. 띄우기가 실패함**
  - 상황: B가 떠 있고, 운영자가 C에서 `start`를 실행했다.
  - 행동: 검사나 띄우기, 준비 확인 가운데 하나가 실패한다.
  - 결과: 지금처럼 원인과 고칠 방법을 보인다. 아무 버전도 지우지 않고, 지금 버전과 직전 버전의 기억도 바꾸지 않는다.
- **S6. 직전 버전을 알 수 없음**
  - 상황: 설치 폴더에 묶음 폴더가 여럿 있는데, 운영 명령이 직전 버전을 기억하지 못하고 떠 있던 버전도 없다. 예: 이 기능 전 묶음으로 `install`만 해 둔 서버에서 새 버전을 처음 띄운다.
  - 행동: 운영자가 `start`를 실행하고 성공한다.
  - 결과: 아무 버전도 지우지 않고, 직전 버전을 몰라 정리하지 않았다는 안내와 손으로 지우는 방법(운영 가이드)을 보인다.
- **S7. 되돌릴 버전이 없음**
  - 상황: 띄운 버전이 하나뿐이거나, 직전 버전의 묶음 폴더가 설치 폴더에 없다.
  - 행동: 운영자가 `rollback`을 실행한다.
  - 결과: 되돌릴 버전이 없다거나, 직전 버전과 그 폴더 이름을 보이며 폴더가 없다고 알린다. 떠 있는 모니터링 시스템을 건드리지 않는다.
- **S8. 지우기가 실패함**
  - 상황: 오래된 버전의 묶음 폴더나 이미지를 지울 수 없다. 예: 권한이 없거나 다른 컨테이너가 그 이미지를 쓴다.
  - 행동: 운영자가 `start`나 `rollback`을 실행하고, 띄우기는 성공한다.
  - 결과: 지우지 못한 대상과 이유를 경고로 보이고, 띄우기는 성공으로 끝난다. 다음 정리 때 다시 지운다.
- **S9. 묶음 폴더처럼 보이지만 지우면 안 되는 대상**
  - 상황: 설치 폴더에 `monitoring-system-`으로 시작하는 링크나, 버전 형식이 아닌 이름의 폴더가 있다.
  - 행동: 운영자가 `start`를 실행하고 성공한다.
  - 결과: 그 링크와 폴더, 링크가 가리키는 곳을 지우지 않는다.
- **S10. 띄우기에 실패한 버전 뒤에 다른 새 버전을 띄움**
  - 상황: B가 정상으로 떴고 직전 버전은 A다. C의 `start`가 준비 확인에서 실패해 C의 컨테이너가 남아 있다. 운영자가 고친 D 묶음 폴더를 옮겼다.
  - 행동: 운영자가 D에서 `start`를 실행하고 성공한다.
  - 결과: 직전 버전은 마지막으로 `start`가 성공한 B다. A와 C를 지우고, B와 D는 남는다.
- **S11. 되돌리다 기록 보관 값 줄임 확인을 거절함**
  - 상황: C가 떠 있고 직전 버전은 B다. 되돌리면 기록 보관 값이 줄어든다.
  - 행동: 운영자가 `rollback`을 실행하고 확인 질문에 `y`가 아닌 답을 넣는다.
  - 결과: C가 그대로 돌고, 되돌리지 않았다고 알리며 실패로 끝난다. 되돌렸다고 보이지 않는다.

### 보안

- 접근 권한: `start`와 같다. Docker를 쓸 수 있고 설치 폴더에 쓸 수 있는 서버 운영자가 실행한다.
- 외부 입력: 설치 폴더 안의 파일·폴더 이름과 종류, 운영 명령이 기억한 버전 값, 서버에 있는 Docker 이미지의 이름과 태그. 지우는 대상은 설치 폴더 바로 아래의 `monitoring-system-<버전>` 형식의 실제 폴더와 `monitoring-system-<프로그램>:<버전>` 이미지로 한정한다. 링크를 따라가지 않고, 설치 폴더 밖을 지우지 않는다.
- 민감한 정보: 없음. token 파일과 `.env`는 읽거나 지우지 않는다.
- 남길 보안 이벤트: 없음. 지운 버전과 되돌린 버전은 명령 출력에 보인다.

### 바뀌지 않는 것

- `start`의 검사, 이미지 불러오기, 띄우기, 준비 확인의 순서와 실패 동작
- 남아 있는 묶음 폴더에서 `start`를 실행해 그 버전으로 바꾸는 방법
- `install`, `render`, `status`의 동작
- 쌓은 기록, 장애 상태, `.env`, token, CA 인증서 파일, `monitoring` 네트워크
- 빌드 PC의 `monitoring-dev.bat`과 저장소에서 실행하는 운영 명령의 동작
