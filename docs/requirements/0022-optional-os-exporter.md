# 0022. 서버 사용량 수집(OS exporter)을 .env로 끔

- 상태: 구현됨
- 작성일: 2026-11-16
- 관련: [#63](https://github.com/subinggrae/server-monitor/issues/63), [0006](0006-os-exporter.md), [0013](0013-core-env-settings.md), [INTEGRATION.md](../INTEGRATION.md)

## 배경

Prometheus는 30초마다 관리자 서버의 `GET /api/prometheus/sd/os-exporter`를 불러 서버 사용량을 모을 대상 목록을 받는다. 서버 사용량 감시를 만들지 않는 관리자 서버는 이 API가 없어 `404` 같은 오류를 돌려준다. 그래도 주소 감시와 장애 알림은 그대로 동작한다. 하지만 Prometheus 로그에 목록을 받지 못했다는 오류가 30초마다 남는다. 운영자는 이 오류가 문제인지 알 수 없다.

관리자 서버가 이 API를 만들지 않을 때는 운영자가 설치 폴더의 `.env`에서 서버 사용량 수집을 끄게 한다(사람 확인: 2026-11-16).

## 목표

- 운영자가 `.env`에 `MONITORING_OS_EXPORTER=off`를 적으면, 모니터링 시스템이 서버 감시 대상 목록 API를 부르지 않고 서버 사용량도 모으지 않는다. 값은 `on`과 `off`이고, 적지 않으면 `on`이다(사람 확인: 2026-11-16).
- 끈 상태에서는 관리자 서버가 그 API에 `404`를 돌려줘도 Prometheus 로그에 오류가 남지 않는다.
- 통합 계약과 관리자 서버 만들기에, 서버 사용량 감시를 만들지 않는 관리자 서버라면 운영자가 이 값을 끈다고 적는다.

## 하지 않는 것

- 주소 감시(`GET /api/prometheus/sd/blackbox`)나 장애 알림(webhook)을 끄는 것
- 사용률을 계산하는 recording rule(`rules/server-resources.yml`)을 빼는 것. 수집하지 않으면 결과가 비어 있을 뿐 오류가 나지 않는다.
- 관리자 서버가 API를 만들었는지 모니터링 시스템이 알아서 판단해 끄는 것. 운영자가 정한다.
- 끄기 전에 모은 서버 사용량 기록을 지우는 것. 보관 기간이 지나면 지금처럼 지워진다.

## 사용자 경험

1. 운영자가 관리자 서버를 만든 쪽에 서버 사용량 감시가 있는지 확인한다.
2. 없으면 설치 폴더의 `.env`에 `MONITORING_OS_EXPORTER=off`를 적는다.
3. `sudo sh monitoring-server.sh start`를 실행한다.
4. `status`의 기본값과 다른 설정 값에 "서버 사용량 수집 꺼짐"이 보인다. Prometheus 로그에 서버 감시 대상 목록 오류가 더는 남지 않는다.

## 동작

### 정상 동작

- **S1. 값을 적지 않거나 on**
  - 상황: `.env`에 `MONITORING_OS_EXPORTER`가 없거나, 비었거나, `on`이다.
  - 행동: 운영자가 `start`나 `render`를 실행한다.
  - 결과: 지금과 같다. Prometheus가 서버 감시 대상 목록 API를 부르고 OS exporter에서 사용량을 모은다. `status`에는 이 값이 보이지 않는다(기본값).

- **S2. off**
  - 상황: `.env`에 `MONITORING_OS_EXPORTER=off`가 있다.
  - 행동: 운영자가 `start`를 실행한다.
  - 결과: 펼친 Prometheus 설정에 서버 사용량 수집(`manager-os`)이 없다. Prometheus는 서버 감시 대상 목록 API를 부르지 않는다. 주소 감시, 장애 판단, webhook은 그대로다. `status`의 기본값과 다른 설정 값에 서버 사용량 수집이 꺼졌다고 보인다.

- **S3. 켜고 끄기를 바꿈**
  - 상황: 모니터링 시스템이 떠 있고, 운영자가 `.env`의 값을 `on`에서 `off`로, 또는 반대로 바꿨다.
  - 행동: 운영자가 `start`를 실행한다.
  - 결과: 바꾼 값으로 다시 뜬다. 끄면 그때부터 서버 사용량을 모으지 않고, 켜면 다음 목록 갱신(30초 안)부터 다시 모은다. 쌓은 기록과 장애 상태는 이어진다. 끄는 것은 기록을 지우지 않으므로 확인을 묻지 않는다.

- **S4. 셸 환경 변수**
  - 상황: 셸 환경 변수 `MONITORING_OS_EXPORTER`가 있다.
  - 행동: 운영자가 `start`나 `render`를 실행한다.
  - 결과: 다른 설정 값처럼 셸 환경 변수가 `.env`보다 먼저 쓰인다.

### 예외 동작

- **S5. 틀린 값**
  - 상황: 값이 `on`, `off`가 아니다. 예: `yes`, `false`, `0`, `ON`
  - 행동: 운영자가 `start`나 `render`를 실행한다.
  - 결과: 다른 설정 값 오류와 같은 형식으로 멈춘다. 형식은 이름, 적힌 값, 문제, 허용 값(`on`, `off`), 고치는 방법이다. 앞뒤 공백은 지금처럼 지우고 본다. 펼친 설정과 떠 있는 컨테이너는 바꾸지 않는다.

### 보안

- 접근 권한: 바뀌지 않는다. `.env`는 설치 폴더에 쓸 수 있는 운영자만 바꾼다.
- 외부 입력: `.env`와 셸 환경 변수의 `MONITORING_OS_EXPORTER`. `on`, `off` 두 값만 받는다. 이 값은 설정 파일에 글자로 펼치지 않고, 수집 부분을 넣을지 뺄지만 정한다.
- 민감한 정보: 없음
- 남길 보안 이벤트: 없음

### 바뀌지 않는 것

- 값을 적지 않은 서버의 동작(서버 사용량을 지금처럼 모음)
- 다른 설정 값의 이름, 허용 범위, 검사
- 주소 감시, 장애 판단 규칙, webhook, 관리자 서버와의 계약 가운데 주소 감시와 장애 부분
- 서버 사용량 수집을 켠 상태의 서버 감시 대상 목록 API 계약
