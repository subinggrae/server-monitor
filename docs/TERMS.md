# 용어

출처끼리 갈려서 하나로 정한 말과 쓰지 않기로 한 말을 적는다. 글을 쓰다가 말을 고를 때는 먼저 이 파일에서 `grep -n 병합 docs/TERMS.md`처럼 찾는다. 여기에 없는 말은 [WRITING.md의 용어](WRITING.md#용어) 순서로 출처를 찾아 쓴다.

`node scripts/check-docs.mjs`가 문서와 그림에서 쓰지 않는 말을 찾아 경고한다. 다만 한글이 없는 말과 괄호로 뜻을 한정한 말은 코드, 주소, 다른 뜻의 낱말과 구별할 수 없어서 검사하지 않는다.

## 개발 용어

개발에 쓰는 말은 다음처럼 정했다.

| 쓰는 말 | 쓰지 않는 말 | 근거 | 확인일 |
|---|---|---|---|
| 저장소 | 리포지토리, 리포지터리, 레포지토리 | Pro Git 한국어판, Git·SVN 메시지 번역(GitLab과 Kubernetes는 리포지토리·리포지터리) | 2026-10-07 |
| 커밋 | 기록(commit의 뜻) | 모든 공식 번역이 커밋(Git 메시지 번역에서 기록은 log) | 2026-10-07 |
| 푸시 | Push, push | Git 메시지 번역, GitLab 화면(Pro Git은 Push) | 2026-10-07 |
| 풀 | Pull, 가져오기(pull의 뜻) | Git 메시지 번역(Pro Git은 Pull, GitHub 문서는 가져오기) | 2026-10-07 |
| 병합 | 머지(merge의 뜻) | Git·SVN 메시지 번역, Kubernetes(GitLab은 머지) | 2026-10-07 |
| 리베이스 | Rebase, 재베이스 | Git 메시지 번역(Pro Git은 Rebase, Microsoft 기계 번역은 재베이스) | 2026-10-07 |
| 스태시 | Stash | Git 메시지 번역(Pro Git은 Stash) | 2026-10-07 |
| 체크아웃 | 체크 아웃 | Git 메시지 번역(TortoiseSVN은 두 표기를 섞음) | 2026-10-07 |
| PR | 풀 리퀘스트, 끌어오기 요청, 리뷰 요청(PR의 뜻) | 표기가 갈려 약어로 씀(GitLab에서 리뷰 요청은 리뷰어 지정) | 2026-10-07 |
| 리뷰 | 검토(review의 뜻) | Kubernetes, Pro Git, GitLab(GitHub와 Microsoft는 검토) | 2026-10-07 |
| 토픽 브랜치 | 작업 브랜치, 기능 브랜치 | Pro Git 한국어판(GitHub와 GitLab은 feature branch) | 2026-10-07 |
| 대상 브랜치 | 기본 브랜치(base branch의 뜻) | GitHub 문서 한국어판이 base와 default를 같은 말로 옮겨 혼동됨 | 2026-10-07 |
| 작업 사본 | 작업사본 | SVN 메시지 번역(TortoiseSVN은 두 표기를 섞음) | 2026-10-07 |
| 허용 목록, 차단 목록 | 화이트리스트, 블랙리스트 | 카카오 문서 스타일 | 2026-10-02 |
| 스크린샷 | 스크린숏 | Apple, Android, Windows 제품 문서(우리말샘의 규범 표기는 스크린숏) | 2026-10-02 |

## 화면 글

사용자에게 보이는 화면 글에 쓰는 말은 다음처럼 정했다.

| 쓰는 말 | 쓰지 않는 말 | 근거 | 확인일 |
|---|---|---|---|
| 로그인 | 접속(log-in의 뜻) | KRDS 로그인 패턴(국립국어원 다듬은 말은 정착률이 낮음) | 2026-10-07 |
| 비밀번호 | 패스워드, 암호(password의 뜻) | KRDS 로그인 패턴(KRDS 안에서도 패스워드를 섞음, Apple은 암호) | 2026-10-07 |
| 감시 항목 | Check, Monitoring Check, 모니터(Check의 뜻) | 제품 개념은 한국어로 쓰고 메뉴와 제목에서만 병기(요구사항 0005, Uptime Kuma는 모니터) | 2026-10-15 |
| 장애 | Alert, 경고(Alert의 뜻) | 감시 단위와 장애 이벤트를 나눔(PagerDuty, Zabbix의 장애, Grafana는 Alert와 Warning이 모두 경고라 겹침) | 2026-10-15 |
| 알림 | 장애(Telegram 발송의 뜻) | 알림은 Telegram으로 보내는 일에만 씀 | 2026-10-15 |
| 복구 | 해소, Resolved | Telegram 메시지와 복구 알림 설정이 이미 복구를 씀(Zabbix, Grafana는 해결됨) | 2026-10-15 |
| 위험, 경고 | Critical, Warning | 상태 이름 위험과 심각도를 한 말로 맞춤 | 2026-10-15 |
| 임계값 | Threshold | Grafana, Zabbix 한국어판 | 2026-10-15 |
| 리소스 | Resource | 굳은 외래어(WRITING.md의 용어) | 2026-10-15 |
| 호스트, 호스트 이름 | Host, hostname | 굳은 외래어(Zabbix 한국어판) | 2026-10-15 |
| 받는 그룹 | 알림 대상(Telegram 그룹의 뜻) | 대상은 확인하는 주소에만 씀 | 2026-10-15 |
| 설정 안 됨 | 미설정 | 설정 화면이 이미 설정 안 됨을 씀 | 2026-10-15 |
| 토픽 ID | Message Thread ID, Topic | 한 칸을 두 이름으로 부르던 것을 하나로 맞춤 | 2026-10-15 |
| OS exporter | 수집 에이전트, OS 수집기(node_exporter와 windows_exporter를 함께 부를 때) | 두 exporter를 한 이름으로 부름(요구사항 0006) | 2026-10-16 |
| 수집 중, 수집 실패, 수집 꺼짐 | 연결됨, 응답 없음(서버 자원 수집 상태의 뜻) | 수집 상태와 서버 생존을 나눔(요구사항 0006) | 2026-10-16 |
| Monitoring Manager | Backend, 서버(이 제품의 뜻) | 서버는 감시하는 서버에만 씀(RULES.md의 화면 글) | 2026-10-15 |
| 닫기 | 취소(창만 닫는 버튼의 뜻) | RULES.md의 화면 글 | 2026-10-15 |
