# 라이선스

이 제품에 들이는 바깥 것의 라이선스를 확인하고 기록하는 규칙이다. 바깥 것은 패키지, 가져온 코드 조각, 글꼴, 아이콘, 이미지, 영상, AI 생성물이다. 상업 서비스를 기준으로 한다. 무엇이든 들이기 전에 읽는다. 법률 판단은 사람이 한다.

- 승인하는 사람: 아직 정하지 않았다. 정할 때까지 작업을 맡긴 사람이 승인한다.

## 분류

| 구분 | 코드와 패키지 | 글꼴 | 아이콘, 이미지, 영상 |
|---|---|---|---|
| 허용 | MIT, Apache-2.0, BSD-2-Clause, BSD-3-Clause, ISC, 0BSD, CC0-1.0 | OFL-1.1 | CC0, CC BY, 공공누리 제1유형, Unsplash·Pexels·Pixabay 라이선스 |
| 승인 필요 | GPL, LGPL, MPL, EPL, CC BY-SA, 상용, 감지하지 못한 라이선스 | 상용 글꼴, 구독 글꼴, 용도를 따로 정한 무료 글꼴 | CC BY-SA, CC BY-ND, 공공누리 제3유형, 유료 스톡, 유료 아이콘 |
| 금지 | AGPL, SSPL, BUSL, Commons Clause, 비상업(NC), 라이선스 없음 | 비영리나 개인 용도로만 허락한 글꼴 | CC BY-NC 계열, 공공누리 제2·4유형, 라이선스를 알 수 없는 것 |

- **허용**: AI가 들이고 [들여온 것](#들여온-것)에 기록한다. 패키지는 lockfile이 기록을 대신한다.
- **승인 필요**: 쓰기 전에 승인하는 사람에게 묻고, 승인한 사람과 날짜를 기록한다. 쓰는 기능이 유료판에만 있으면 상용으로 본다.
- **금지**: 쓰지 않는다. AGPL은 서비스를 네트워크로 쓰기만 해도 소스를 제공할 의무가 생긴다.
- 표에 없는 라이선스는 승인 필요로 본다. 함께 설치되는 간접 의존성도 같은 표로 확인한다.
- 버전을 올릴 때도 라이선스를 다시 확인한다. 새 버전에서 라이선스가 바뀌는 일이 있다.

## 확인할 것

- 라이선스는 원본 저장소나 공식 배포처의 라이선스 원문에서 확인한다. AI가 기억하는 라이선스 정보와 모아 둔 사이트의 표시는 근거가 아니다.
- 라이선스를 표시한 곳이 실제 권리자인지 확인한다. 공공기관 누리집이 공공누리를 표시했어도 사진에 기자나 통신사 표시가 있으면 권리자는 그 사람이다. 이런 것은 승인 필요로 본다.
- 저작권 라이선스는 초상과 상표를 허락하지 않는다. 알아볼 수 있는 사람, 상표, 로고, 미술품이 담긴 것은 승인 필요로 본다. 추천이나 보증처럼 보이게 쓰지 않는다.
- 회사가 가진 사진, 일러스트, 영상, 글꼴도 원래 계약이 허락한 용도 안에서만 쓴다. 외주로 만든 것을 새 화면이나 다른 매체에 다시 쓰면 승인 필요로 본다.

## 글꼴

글꼴은 용도마다 허락이 따로 있다. 웹 폰트로 서버에 올리기, 이미지나 영상의 글자, 로고와 CI, 앱에 넣기가 각각 다르다. "상업 이용 가능"이라는 표시만 보고 웹 폰트로 쓰지 않는다.

- 운영체제에 들어 있는 글꼴은 CSS `font-family`에 이름만 쓴다. 그 파일을 서버에 올리거나 WOFF로 바꾸지 않는다.
- 서브셋을 만들거나 형식을 바꾸는 것도 수정이다. OFL 글꼴은 라이선스의 Reserved Font Name을 확인하고, 선언이 있으면 수정한 파일에 원래 이름을 쓰지 않는다. 예: Pretendard
- 글꼴 파일만 따로 팔거나 내려받게 하지 않는다.

## 아이콘과 이미지

- 아이콘은 쓰는 파일 형식의 라이선스를 본다. 같은 아이콘 세트도 SVG, 글꼴 파일, 코드의 라이선스가 다를 수 있다.
- 파일 안의 저작권 표시와 라이선스 주석을 지우지 않는다.
- 스톡 이미지를 고치지 않고 상품으로 팔거나, 모아서 다시 배포하지 않는다.

## 코드 조각

- 웹에서 가져온 코드 조각에는 출처 주소와 라이선스를 주석으로 남긴다. 예: `// 출처: https://example.com/snippet (MIT)`
- Stack Overflow 답변은 CC BY-SA라 승인 필요로 본다. 승인받지 않으면 동작을 이해한 뒤 직접 다시 쓴다.
- 라이선스가 없는 블로그와 저장소의 코드는 쓰지 않는다.
- 오픈소스 파일을 고쳐서 넣었으면 그 파일에 고친 사실을 남긴다.

## AI 생성물

- AI는 알려진 오픈소스 구현을 기억으로 길게 재현하지 않는다. 특정 프로젝트의 코드를 옮기면 출처와 라이선스를 밝히고 [분류](#분류)를 따른다.
- 코딩 도구에 공개 코드와 일치하는 제안을 막는 설정이 있으면 켠다.
- 이미지 생성 서비스와 요금제는 사람이 정한다. 상업 이용 조건과 면책 조건이 서비스마다 다르다. AI는 정한 서비스만 쓴다.
- 실존 인물, 다른 회사의 상표와 캐릭터, 특정 작가의 화풍을 겨냥한 프롬프트를 쓰지 않는다. 결과에 워터마크, 로고, 서명이 보이면 쓰지 않는다.
- AI 생성물은 저작권으로 보호받지 못할 수 있고, 다른 사람도 같은 결과를 얻을 수 있다. 로고처럼 독점해야 하는 곳에 쓸지는 사람이 정한다.
- 제품이 생성 AI API를 직접 부르면, 그 서비스의 면책을 유지하는 조건을 사람이 확인한다.

## 고지

- 출처 표시가 필요한 것(Apache-2.0의 NOTICE, CC BY, 공공누리, OFL)은 오픈소스 고지 화면에 싣는다. 고지 화면은 설정이나 서비스 정보 화면에서 링크한다. 패키지로 들인 것도 고지는 필요하다. lockfile은 기록만 대신한다. 고지 화면이 아직 없으면 고지가 필요한 것을 들인 변경의 보고에 적고, 고지 화면을 만들자고 제안한다.
- 프로덕션 빌드는 번들한 패키지의 라이선스 파일을 만든다. 라이선스 주석을 지우는 설정(esbuild `legalComments: 'none'` 등)을 쓰지 않는다.
- 라이선스 파일 설정: 아직 정하지 않았다. `frontend/vite.config.ts`에 `build.license` 설정이 없다.
- 라이선스 검사: 아직 정하지 않았다. 도구를 정한다.

## 사람이 하는 일

AI는 라이선스를 찾고, 분류 표와 대조하고, 기록과 고지 파일을 만들고, 어긋난 것을 보고한다. 다음은 사람이 한다.

- 승인 필요 항목을 승인하고 분류 표를 바꾸는 일
- GPL 계열 코드를 어떻게 결합할지 해석하는 일
- 상용 라이선스와 생성 AI 서비스를 계약하는 일
- AI 생성물의 권리를 판단하는 일
- 라이선스 위반을 알리는 연락(내용증명, 합의금 요구)에 답하는 일. AI는 답하지 않고 사람에게 넘긴다.
