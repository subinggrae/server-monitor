# 제품

누가 무엇을 하려고 이 제품을 쓰는지, 어떤 환경에서 쓰는지, 요구사항과 구현을 묶는 제약은 무엇인지, 운영자에게 보이는 글은 어떤 말투로 쓰는지와 그 근거를 적는다. 이런 사실은 구현이 바뀌어도 오래 유지된다. 요구사항을 쓸 때, 그리고 운영 명령의 안내나 장애 문구처럼 운영자에게 보이는 글을 쓸 때 이 문서를 읽는다.

## 대상과 목적

이 제품을 쓰는 사람과 그 사람이 이 제품으로 하는 일을 적는다.

- 대상
  - 사내 운영 담당자: 모니터링 서버에 모니터링 시스템을 설치하고, 운영 명령으로 띄우고 갱신한다. 개발에 참여하지 않은 사람일 수 있다.
  - 관리자 서버 개발자: 모니터링 시스템에 붙일 관리자 서버를 [통합 계약](INTEGRATION.md)대로 만든다.
- 목적: 서버와 서비스가 살아 있는지 확인하고, 서버의 CPU, Memory, Storage 사용량을 모으고, 장애를 관리자 서버에 보낸다. 무엇을 감시할지와 누구에게 어떤 수단으로 알릴지는 관리자 서버가 정한다.
- 가장 자주 하는 일: 운영 담당자가 모니터링 시스템을 새 버전으로 갱신하고 상태를 확인한다.

## 사용 환경

이 제품이 도는 곳과 운영자가 다루는 방식을 적는다.

- 모니터링 서버: 사내망의 Linux 서버에 Docker 컨테이너로 띄운다. 인터넷이 없어도 된다. 관리자 서버와 같은 서버에 둔다.
- 빌드 PC: Windows PC에서 묶음을 만들어 모니터링 서버로 옮긴다.
- 운영자는 SSH로 모니터링 서버에 접속해 운영 명령을 실행하고, 필요할 때만 상태를 본다.

## 제약

요구사항과 구현을 묶는 조건을 적는다.

- 모니터링 시스템과 node_exporter 묶음에는 그 묶음의 프로그램(Apache-2.0) 밖의 라이선스를 더하지 않는다. 그래서 이미지에 셸과 도구를 넣지 않는다([LICENSES.md의 고지](LICENSES.md#고지)).
- 모니터링 시스템의 포트는 모니터링 서버의 `127.0.0.1`에만 연다.
- 운영자에게 보이는 글(운영 명령의 안내, 장애 문구, 운영 가이드)은 한국어로 쓴다. 장비나 외부 서비스에서 그대로 찾아야 하는 이름(Prometheus, Alertmanager, node_exporter, windows_exporter, Docker)은 영어로 쓴다. 정한 표기는 [TERMS.md](TERMS.md)에 둔다.
- 관리자 서버의 화면에 쓸 말은 [TERMS.md의 화면 글](TERMS.md#화면-글)을 권한다. 관리자 서버의 화면과 시각 체계는 관리자 서버를 만드는 쪽이 정한다.

## 말투

운영자에게 보이는 글의 문체와 어조를 적는다.

- 문체: 합니다체. 운영자에게 확인을 받는 질문만 해요체로 쓴다. 예: `계속할까요?`
- 어조: 짧고 구체적으로 쓴다. 상황, 결과, 할 일만 쓰고 비유를 쓰지 않는다. 하지 못한 일과 다음에 할 일을 함께 쓴다. 예: `Docker에 연결하지 못했습니다. Docker가 실행 중인지 확인해 주세요.`
